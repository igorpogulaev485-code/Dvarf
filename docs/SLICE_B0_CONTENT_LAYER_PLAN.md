## Что делаем в B0 (минимально)

### 1. Поле / тег `content_layer`

Значения:

| Значение | Когда |
| --- | --- |
| `srd` | Есть в официальном SRD (CC BY) |
| `community_ref` | Официальная книга вне SRD (PHB gap, XGE, MM, MPMM…) |
| `user_import` | Залил пользователь (пока редко / заготовка) |
| `homebrew` | Своё (уже есть «Хомбрю» у кастом-спеллов) |

### 2. Где проставляем (пилот → остальное)

**Пилот (в этом слайсе обязательно):**

1. **Заклинания** — уже почти размечены по факту (SRD ≈319 + хвост книг) → проставить явно.
2. **Расы** (spec JSON) — почти всё `community_ref`, проставить.

**В том же слайсе, если тянется без боли:**

3. Черты, классы/features — по тому же правилу.  
4. Бестиарий — counts + тег (объём большой; можно добить вторым микрошагом, если первый затянется).

### 3. Что **не** делаем

- Не удаляем карточки  
- Не прячем каталог за paywall  
- Не показываем ярлыки в UI игроку  
- Не ломаем ttg-парсеры в этом слайсе (это B2)  
- Не меняем тексты `/legal` снова  

### 4. Артефакт для нас

Команда/отчёт: **counts × kind × content_layer**  
(сколько srd / community_ref по заклинаниям, расам, …).  
Это и есть «скрины» B0: не картинка UI, а таблица counts + проверка «каталог на месте».

## Как поймём, что готово (acceptance)

1. У размеченных сущностей есть `content_layer`, без «пустых».  
2. Counts по слоям есть (скрипт или вывод в docs/логе).  
3. Каталог в приложении как был (раса/спелл открываются).  
4. Игрок не видит новых бейджей «SRD / community».  
5. Скрины/таблица → твой ok → прод.
