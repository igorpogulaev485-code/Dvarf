# Генерация имени персонажа — план (v2)

Связано с create pipeline (2014), шаг **Раса**.  
Прод: поле «Имя персонажа» уже есть; генерации и таблиц имён в справочнике рас нет; поля пола нет.

## Решения продукта (зафиксировано)

| Тема | Решение |
|------|---------|
| Пол | **Нужен.** Выбор на шаге расы + хранение + отображение на листе |
| Гейт пола | **Без выбора пола «Далее» недоступно** (`gender === null`) |
| Небинарный / имена | Пул **`any` (нейтральные)**; если пуст — случайно из `male∪female` |
| Контент имён | **Максимум** по всем расам каталога; эталон полноты — **тифлинг** |
| Где генерация | **Только в создании** (create pipeline). На карточке/листе кнопки нет |
| Ручной ввод | Всегда доступен; генерация не блокирует и не обязательна |
| Порядок в диалоге | **Подраса → пол → имя** (генерация ждёт выбранную разновидность) |

## Цель

1. На шаге «Раса» игрок выбирает **пол** и при желании жмёт **«Сгенерировать»** — подставляется расово уместное имя с учётом пола и naming-спеки расы.
2. Имя и пол уходят в персонажа; пол виден на **цифровом** и **классическом** листе.
3. Справочник рас дополняется богатыми таблицами имён (паттерны + пулы).

## Как сейчас

| Что | Состояние |
|-----|-----------|
| UI создания | `CreateCharacterPage`, шаг `race`: свободный `Input` «Имя персонажа» |
| Гейт | «Далее» / «Готово» требуют `characterName.trim()` |
| Каталог рас | `phb2014` / `mpmm` / `setting` specs → `catalog_entries.data` — **без** `naming` |
| Пол | Нет ни в pipeline state, ни в `sheet.identity` |
| Классический лист P2 | Physique: возраст / рост / вес / глаза / кожа / волосы — **пола нет** (в PHB-бланке Sex обычно рядом) |
| API имени | `String(120)`, без уникальности |

## 1. Пол

### Значения

```ts
type CharacterGender = 'male' | 'female' | 'nonbinary' | 'unspecified'
```

UI-лейблы (RU): Мужской / Женский / Небинарный / Не указан.

**Гейт:** в pipeline `gender: CharacterGender | null`, старт = `null` (ничего не выбрано).  
«Далее» / done-gate шага расы: `gender != null` **и** `characterName.trim()`.  
«Не указан» — валидный **явный** выбор (игрок сам нажал), не тихий дефолт.

### Генерация имён по полу (как правильно)

| Выбранный пол | Откуда брать given/аналог |
|---------------|---------------------------|
| `male` | только `pools.*.male` (fallback: `any`, потом ошибка/disabled) |
| `female` | только `pools.*.female` (fallback: `any`) |
| `nonbinary` | **сначала `any`** (нейтральные/unisex формы) |
| `unspecified` | как `nonbinary` — не навязываем М/Ж |

Если для `nonbinary` / `unspecified` пул `any` пуст — **равномерно** `male ∪ female` (не «подставить мужской по умолчанию»).

Почему так:
- отдельный ключ `nonbinary` в JSON не нужен — это тот же смысл, что `any`/unisex;
- небинарность ≠ «случайный пол персонажа», поэтому сначала нейтральные имена;
- у рас с naturally unisex именами (добродетели тифлинга, обозначения варфорджа, часть kenku/warforged) `any` наполняем щедро — это и есть правильный контент для nonbinary;
- gendered clan/family обычно общие для всех полов.

### Где хранить

| Слой | Поле |
|------|------|
| Pipeline state | `gender: CharacterGender` (+ draft localStorage / БД draft) |
| Sheet | `sheet.identity.gender` (строка enum) |
| Колонка `characters` | **не** дублируем на v1 — достаточно identity в JSONB sheet |

Apply create pipeline пишет `identity.gender` вместе с именем.

### Где показать на листе

1. **Классический 2014 P2** — в ряд `classic-physique` добавить **«Пол»** (ключ `gender`), рядом с возрастом/ростом (как Sex на бумажном бланке).
2. **Цифровой лист** — в блоке «Основное» / IdentityDialog: select/сегмент пола (редактирование после создания — да; **генерация имени** после создания — нет).
3. Опционально позже: краткая строка в шапке Play Desk — **не** в скоупе первой поставки.

## 2. Naming в справочнике рас

Расширяем `data` корневой расы (подраса наследует; override целиком при необходимости).

```ts
type NamingGender = 'any' | 'male' | 'female'

interface NamingPool {
  any?: string[]
  male?: string[]
  female?: string[]
}

interface NamingPattern {
  id: string
  /** '{given}' | '{given} {clan}' | '{given} {family}' | '{virtue}' | '{prefix}{stem}{suffix}' */
  template: string
  weight?: number
  /** Если задан — pattern доступен только при этом режиме (тифлинг) */
  mode?: string
}

interface NamingSpec {
  /** Именованные режимы генерации (UI-сегмент, если length > 1) */
  modes?: Array<{ id: string; labelRu: string; weight?: number }>
  patterns: NamingPattern[]
  pools: Record<string, NamingPool | string[]>
}
```

Генератор (клиент):

1. Резолв: naming подрасы → корня → global fantasy fallback.
2. Если у расы несколько `modes` — либо случайный по weight, либо выбранный в UI (тифлинг: показываем режимы).
3. Фильтр pattern по `mode`.
4. Выбор pattern → заполнение плейсхолдеров с учётом `gender`.
5. Trim, ≤120 символов → `characterName`.

## 3. Эталон: тифлинг (максимум)

Тифлинг задаёт планку полноты контента и UX режимов.

| Mode id | labelRu | Паттерны | Пулы |
|---------|---------|----------|------|
| `virtue` | Добродетель | `{virtue}` | добродетели RU (Смелость, Надежда, Страх, …) — без пола |
| `infernal` | Инфернальное | `{given}` / `{given} {clan?}` | male/female инфернальные given + опц. прозвища |
| `abyssal` | Бездны | `{given}` | более жёсткие/шипящие формы |
| `cultural` | По крови предков | как human/elf mix | ссылка на пулы человека (или локальная копия) |

UI на шаге расы при выбранном тифлинге: сегмент режимов над/рядом с «Сгенерировать».  
Повтор клика крутит внутри текущего режима; смена режима → сразу новое имя.

Объём контента-ориентир для тифлинга: **≥30** virtue, **≥40** given на пол, **≥15** clan/epithet — чтобы повторы были редкими.

## 4. Контент по всем расам

Цель первой поставки контента — **не** «только PHB», а **все корни** активного каталога (PHB + MPMM + setting), с богатыми пулами. Подрасы с особым колоритом — override.

### PHB

| Раса | Паттерны | Заметки |
|------|----------|---------|
| Дварф | `{given} {clan}` | gendered given; clan общий; дуэргар — override тона |
| Эльф | `{given}`, `{given} {family}` | high/wood; **дроу** — отдельный naming |
| Полурослик | `{given} {family}` | + лёгкие nick-паттерны |
| Человек | `{given} {family}` | широкие gendered пулы |
| Драконорождённый | `{given}`, `{given} {clan}` | драконьи кланы |
| Гном | `{given} {clan}`, nick | rock/forest; дикий — более «природный» тон |
| Полуэльф | patterns ∪ пулов elf+human | |
| Полуорк | orcish `{given}` ∨ human pattern | |
| Тифлинг | см. §3 | эталон |

### MPMM (корни) — тоже максимум, не «заглушка»

Aarakocra, aasimar, bugbear, centaur, changeling, fairy, firbolg, genasi (+подтипы), gith (yanki/zerai), goblin, goliath, harengon, hobgoblin, kenku, kobold, lizardfolk, minotaur, orc, satyr, shifter, tabaxi, tortle, triton, yuan-ti — у каждой:

- ≥1 осмысленный pattern (не только `{given}`);
- gendered given где это культурно уместно;
- clan/family/epithet/syllable по лору расы.

### Setting

Warforged / autognome — «сборочные» имена; custom_lineage — fallback fantasy; kalashtar, loxodon, vedalken, owlin, … — свои пулы, не пустые.

### Качество

- Русские формы (дух dnd.su / ttg), не сырой английский оптом.
- Curated списки достаточного размера (ориентир как у тифлинга), чтобы 10 подряд генераций редко совпадали.
- Юридически: свой набор, вдохновлённый PHB Names, без копипаста чужих баз целиком.

## 5. UX создания (только здесь генерация)

На правой панели шага «Раса» → диалог настройки:

1. Карточка расы / «Выбрать и настроить».
2. **Подраса / разновидность** (если есть) — **раньше имени**, т.к. naming зависит от подрасы (дроу ≠ высший эльф).
3. **Пол** — сегмент; пока `null` — «Применить» / «Далее» disabled.
4. **Имя** — Input + «Сгенерировать» (disabled без подрасы при fork и без пола).
5. Если `modes.length > 1` — сегмент режима (тифлинг, полуорк…).
6. Дальше ASI / навыки / … как раньше.
7. «Далее» на шаге: `gender != null` **и** `characterName.trim()` **и** раса применена.

Поведение:

- Нет расы → генерация disabled.
- Смена расы / подрасы / пола / режима → имя **не** авто-переписываем; следующий клик генерации учитывает новый контекст.
- После «Готово» на листе имя и пол редактируются вручную; кнопки генерации нет.
