# Генерация имени персонажа — план

Связано с create pipeline (2014), шаг **Раса**.  
Прод: поле «Имя персонажа» уже есть; генерации и таблиц имён в справочнике рас нет.

## Цель

Кнопка **«Сгенерировать»** рядом с полем имени подставляет расово уместное имя (иногда из нескольких частей). Игрок всегда может править, стереть или ввести своё — генерация не заменяет и не блокирует ручной ввод.

## Как сейчас

| Что | Состояние |
|-----|-----------|
| UI | `CreateCharacterPage`, шаг `race`: `Field` «Имя персонажа» → свободный `Input` |
| Гейт | «Далее» / «Готово» требуют `characterName.trim()` |
| Каталог рас | `catalog_entries.data` из `phb2014` / `mpmm` / `setting` specs — **без** naming |
| Пол | В модели персонажа нет |
| API имени | `String(120)`, без уникальности |

## Модель данных

Расширяем `data` записи расы (JSON в spec → upsert-миграция). Отдельная таблица на v1 не нужна.

```ts
type NamingGender = 'any' | 'male' | 'female'

interface NamingPool {
  /** Нейтральные / общие формы */
  any?: string[]
  male?: string[]
  female?: string[]
}

interface NamingSpec {
  /** Шаблоны с весами; один выбирается случайно */
  patterns: Array<{
    id: string
    /** '{given}' | '{given} {clan}' | '{given} {family}' | '{a}{b}{c}' (syllable) */
    template: string
    weight?: number
  }>
  pools: {
    given?: NamingPool | string[]
    clan?: string[]
    family?: string[]
    /** syllable-mode */
    prefixes?: string[]
    stems?: string[]
    suffixes?: string[]
    /** тифлинг virtue и т.п. */
    virtue?: string[]
    infernal?: string[]
  }
  /**
   * Подраса без своего naming → взять у родителя.
   * Явный `naming` на подрасе перекрывает родителя целиком.
   */
}
```

Генератор (клиент):

1. Резолв naming: выбранная подраса → иначе корень → иначе global fallback.
2. Выбор pattern по weight.
3. Для каждого плейсхолдера — случайный элемент из пула (с учётом опционального фильтра пола).
4. Склейка, trim, обрезка до 120 символов.
5. `patchState({ characterName })` — тот же путь, что ручной ввод.

## Паттерны по расам (контент)

| Раса | Паттерн | Пример |
|------|---------|--------|
| Дварф | `{given} {clan}` | Баренд Камнемолот |
| Эльф | `{given}` (+ опц. `{family}`) | Аэлар / Аэлар Аметистолист |
| Полурослик | `{given} {family}` | Перрин Подхолм |
| Человек | `{given} {family}` | Мара Ветрова |
| Драконорождённый | `{given} {clan}` | Меджик Фаэтран |
| Гном | `{given} {clan}` | Ним Колескин |
| Полуэльф | пулы эльф ∪ человек | — |
| Полуорк | orcish ∨ human pattern | Гром / Карел |
| Тифлинг | virtue ∨ infernal given | Смелость / Акменос |

Ориентир по духу: PHB «Names» + русские формы как в наших справочниках.  
Списки — **curated** (десятки на пул), не полный копипаст чужих таблиц.

## UX

1. Поле имени без изменений (placeholder «Имя героя»).
2. Кнопка/иконка «Сгенерировать» рядом с полем:
   - `disabled`, пока раса не выбрана (или пока нет resolved naming / fallback всегда доступен).
   - Повторный клик → новое имя, без confirm.
3. После генерации поле остаётся editable.
4. Смена расы **не** затирает уже введённое/сгенерированное имя.
5. Генератор всегда читает **текущую** расу/подрасу из state.

### Пол (решение v1 — зафиксировать на ревью)

**Рекомендация:** в модель персонажа пол не добавляем.  
Варианты UI:

- **A (проще):** только нейтральные / смешанные пулы `any`.
- **B:** компактный сегмент М / Ж / · у кнопки генерации, только для выбора пула, без персиста.

## Слайсы

| # | Слайс | Состав |
|---|-------|--------|
| 0 | Контракт | `NamingSpec` + `generateRaceName()` + тесты шаблонов |
| 1 | Контент PHB | `naming` в `phb2014_race_catalog_spec.json` + alembic upsert |
| 2 | UI | Кнопка на шаге расы в `CreateCharacterPage` |
| 3 | MPMM | naming у основных корней MPMM |
| 4 | Setting / edge | setting races + fallback для пустых |
| 5 | Опционально | Та же кнопка на карточке / классическом листе при переименовании |

Деплой — обычным tip-релизом после UI+PHB (слайсы 0–2 достаточно для первой поставки).

## Не в скоупе v1

- Генерация для редакции 2024 (другой поток создания).
- Уникальность имён в аккаунте.
- LLM / внешние API имён.
- Обязательный пол персонажа как поле листа.

## Открытые вопросы

## Критерии готовности (после реализации 0–2)

- [ ] На шаге расы можно сгенерировать имя при выбранной PHB-расе.
- [ ] Можно вручную ввести любое имя; генерация не обязательна.
- [ ] Повтор генерации даёт другое значение с заметной вероятностью.
- [ ] Имя уходит в черновик / «Готово» тем же полем `characterName` / `name`.
- [ ] Расы без своего `naming` не ломают UI (fallback или disabled + пояснение).
