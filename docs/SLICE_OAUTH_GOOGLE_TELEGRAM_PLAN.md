# План слайса: OAuth Google + Telegram (не-РФ / экспорт)

**Статус:** **отложено** · не первостепенно (Игорь, 2026-10-20)  
Яндекс + VK на проде закрыты; Google/TG **не** стартуем, пока не скажешь ok.  
**Контур (когда вернёмся):** план → **ok** → код → скрины → **ok** → прод  
**Зачем документ жив:** для зоны вне РФ позже понадобится привычный вход — план уже готов.

---

## Зачем

| Зона | Что привычно |
| --- | --- |
| РФ / СНГ | Яндекс, VK ID |
| Не-РФ / англоязычные / путешествия | **Google**; часто ещё **Telegram** (без магазина приложений) |

Без Google зарубежный пользователь часто не дойдёт до email-регистрации.

---

## Рекомендация

| Провайдер | Брать? | Почему |
| --- | --- | --- |
| **Google** | **Да, обязательно** для не-РФ | Стандарт веба; один тап; доверие |
| **Telegram Login Widget** | **Да, имеет смысл** | Много игроков DnD в TG; простой виджет; меньше возни с Apple |
| Apple | Не в этом слайсе | Нужен только если будет iOS-приложение / жёсткое требование App Store |

Показ кнопок: можно **все доступные** сразу (Яндекс+VK+Google+TG), либо позже «умные» по локали — не усложняем в первой версии Google/TG.

---

## Порядок (не смешивать с РФ-слайсом)

1. Сначала закрыть **Яндекс + VK** (`SLICE_OAUTH_YANDEX_VK_PLAN.md`) — ok → код → скрины → прод.  
2. Потом этот слайс: **Google + Telegram**.

Так не раздуваем один PR и проще отладить redirect/секреты.

## Что войдёт в слайс (когда дойдём)

1. Google OAuth (клиент в Google Cloud, redirect `https://creed20.tech/...`).  
2. Telegram Login Widget (бот + domain creed20.tech).  
3. Те же правила UI: только рабочие кнопки, без «заглушка».  
4. Скрины входа → ok → прод.

## Что нужно от тебя к старту кода этого слайса

- Google Cloud проект / OAuth client (или ок, что создадим чеклист и ты вставишь Client ID/Secret в секреты).  
- Telegram-бот для Login Widget (или создадим по шагам).
