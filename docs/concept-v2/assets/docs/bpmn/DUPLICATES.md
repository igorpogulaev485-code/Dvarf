## Что сознательно не считалось дублем

- **Классический бланк vs Play Desk.** По контракту `docs/CLASSIC_SHEET_PROD.md` бланк — read-only печать того же `CharacterDetail`. Пишет только настройки печати. Это не второй редактор, если так и оставить.
- **Чат / шепоты / письма / заметки / журнал кампании.** Живут только в лобби, на лист не пересекаются (кроме итога сессии в журнале).
- **Наблюдатель и сомастер.** Это роли входа, не копия функций листа.
- **Два WebSocket** (`/lobbies/{id}/ws` и `/sessions/{id}/ws`) — разные комнаты, не дубль предметной функции. `party_rest` рассылается в оба.

## Решения

Игорь принял все 18 пунктов 21.11.2026, 13:16–13:21 (Екатеринбург, UTC+5). Ниже — принятые формулировки. Тот же текст записан в `/workspace/dark-theme-concept/DECISIONS.md`, раздел «BPMN-дубли» (Б.1–Б.18).

**Общий принцип.** Со стола тоже идут изменения — они сохраняются в лист (запись персонажа) через общий сервис записи с проверкой версии; у стола нет своей параллельной копии данных; открытый лист подхватывает изменение сразу.

1. **Хиты.** Один сервис записи, стол меняет через него, без второго полного редактора.
2. **Атака.** Один серверный расчёт, два входа (стол мастера, лист игрока).
3. **Состояния.** Одно окно; за столом запись через сессию, вне стола PATCH листа.
4. **Отдых.** Одно окно, партийный контекст явно, без тихого пропуска.
5. **Кубики.** Пока герой за столом, каждый бросок с листа идёт в ленту сессии; вне стола журнал личный; секретные броски мастера скрыты.
6. **Инициатива.** В бою бросок только у слота стола, лист показывает бонус.
7. **Напарники.** Один редактор (лист); стол — карточки, бой и «сюжетный» мастера.
8. **Спасброски от смерти.** Ввод на листе, стол показывает.
9. **Инвентарь.** «Передать» (игрок) и «Награда» (мастер) разные сценарии, пишут в один инвентарь, второго «Передать» на столе нет.
10. **Реакции.** «Объявить» открывает реакции листа и тратит реакцию хода, сервер не даёт вторую.
11. **Вдохновение.** Один индикатор, мастер выдаёт/снимает, игрок тратит.
12. **Опыт.** За столом выдаёт мастер, прокачка и выборы уровня на листе.
13. **Эффекты / концентрация.** Один слой на персонаже, стол не хранит свой.
14. **Приветствие.** Один раз на списке; туры листа и лобби раздельно.
15. **Создание для лобби.** «Герой для лобби» и копия — добавить и для 2024.
16. **Правила старта.** Одна сводка-компонент во всех входах + проверка способа генерации характеристик и стартового набора.
17. **Версии.** Любая запись из лобби через проверку версии листа; классический бланк игровые поля не пишет.
18. **Цель.** Цель — окно стола, своё число — в потоке кубиков, поля «цель» в бою нет.

## Как читать это в следующих концептах

Эти решения — обязательный вход для концептов создания персонажа, классического листа и лобби.

**Создание.** Строки 15 и 16 приняты: «герой для лобби» и копия должны быть и для 2024; сводка правил старта — один компонент во всех входах, плюс проверка способа генерации характеристик и стартового набора. Стартовый набор и уровень по-прежнему связаны с выдачей инвентаря и XP (9, 12).

**Классический лист.** Не повторять редакторы хитов, состояний, напарников и вдохновения. Бланк читает те же поля и не пишет игровые данные; запись из лобби идёт через проверку версии листа (строка 17). Страницы напарников бланка показывают тех же существ, что лист и стол (строка 7).

**Лобби.** Стол — витрина и пульт мастера над теми же данными листа, без своей параллельной копии. Изменения со стола пишутся в запись персонажа через общий сервис с проверкой версии; открытый лист подхватывает их сразу. Действуют пункты 1–13 и 18.
