# Задание Cursor Project: производство утверждённого концепта КриD20

Это готовый текст задания координатору облачных агентов в репозитории [https://github.com/igorpogulaev485-code/Dvarf](https://github.com/igorpogulaev485-code/Dvarf).

**Проект из хода сборки пакета не запускать.** В Dvarf из этого пакета ничего не пушить, пока Игорь не посмотрит пакет и не даст отдельную команду на запуск.

Язык работы и UI — русский. Даты и отчёты — Екатеринбург (UTC+5).

## Цель

Перенести в код продукта **уже утверждённый** концепт КриD20 (визуальный язык v2 и принятые экраны) так, чтобы не потерять ни одной функции прода и ничего не выдумать. Концепт сам по себе не релиз: релиз — только после мержа и деплоя, которые делает **только Игорь**.

Пакет материалов (этот каталог и указанные исходники концепта) проект должен получить **как файлы в репозитории**. Предлагаемый путь: `docs/concept-v2/`. Состав копирования — в конце файла и в `FILEMAP.md`. Архив `production-package.zip` прилагается к показу Игорю; в Dvarf его не пушить, пока нет команды.

## Главные правила проверки (читать первыми)

Полный свод — `RULES.md`. Два правила, добавленные 22.11.2026 утром, обязательны на каждом этапе.

### 1. Скрупулёзная проверка этапа (Игорь, 22.11.2026, 10:01)

Каждый этап проверять очень скрупулёзно:

1. Не потерялась ли ни одна функция прода — чек-лист переноса функций по каждому экрану, сверка с прод-кодом `origin/main`.
2. Нет ли двойного пути к одному и тому же (дубли кнопок и входов в одном контексте).
3. Логика отрабатывает правильно (сценарии, состояния, роли мастер / игрок, гость, 2014 / 2024).
4. Ничего не сломать, особенно 2014.

Тестер каждого этапа заполняет эти четыре пункта **отдельным разделом** отчёта по шаблону `CHECKLIST-FUNCTIONS.md`. Без заполненного чек-листа этап не принимать.

**При любых вопросах агенты не угадывают.** Они спрашивают Игоря (он отвечает): вопрос с вариантами, рекомендацией и полем для его ответа — и ждут. Пока ответа нет, спорный кусок не внедрять.

### 2. К20 и подложки только из одного эталона (Игорь, 22.11.2026, 10:02)

В новых макетах снова оказывались не тот к20 и подложки без рисунков.

- Кубик C и 12 подложек берутся **только** из `css/shared-approved.css` (в концепте; в репо — соответствующая копия в `docs/concept-v2/` и затем в UI-ките) и **не рисуются заново**.
- Файл уже есть в концепте: `css/shared-approved.css` (22.11.2026, около 10:09). Копия в пакете: `assets/css/shared-approved.css`. Подключать после CSS темы и `css/mobile-chars-nav.css`. Не копировать кубик из `css/mobile-chars-nav.css` (56×56 / 28px — не вариант C). Не оставлять плоский фон без SVG-тайла.
- **Обязательная автопроверка кадров каждого этапа** против эталона к20 и подложек. Тестер **отклоняет этап** при расхождении. Ручного «похоже» мало.

## Прочие жёсткие правила (кратко)

Дословно и полностью — `RULES.md`.

- В `main` мержит и деплоит только Игорь. Агенты **не мержат**. Ветки не удалять, PR не закрывать без его решения. Один PR на этап, без мержа.

## Этапы внедрения (предлагаемый порядок)

Каждый этап = отдельная ветка + PR **без мержа** + отдельный агент-тестер. Лобби «Лобби / Стол / Мир» — только последним, когда макеты приняты. Конструктор аватарки в эти этапы не входит.

### Этап 0. Подготовка репозитория и общего эталона к20 / подложек

- Положить пакет в `docs/concept-v2/` (после команды Игоря на запуск).
- Взять уже готовый `css/shared-approved.css`, влить кубик C и 12 подложек в UI-кит, не перерисовывая. Подключать после темы и старых стилей оболочки, чтобы перебить 56×56. Подготовить скрипт автосравнения кропов к20 и фона с эталонными кадрами из `DICE.md` / `BACKGROUNDS.md`.
- Критерий: файл-эталон один; скрипт автопроверки гоняется на эталонных кадрах и находит эталон как совпадение, а заведомо старый кубик 56×56 / плоский фон — как провал.
- Тестер: прогон скрипта, md5 тройки HTML не изменились, в кит не попали секреты.

### Этап 1. Кит, токены, темы L3/I2, шрифты, акценты

- Читать: `UIKIT.md`, `BACKGROUNDS.md`, `DICE.md`, CONCEPT §13, §24, §25.
- Сделать в продукте две темы и кастомизацию по принятым правилам (аккаунт, дефолты Пергамент / Чернила / Антиква / Листва). Стили только через кит.
- Критерии: темы и подложки совпадают с эталоном; карточки без паттерна; автопроверка к20 (если кнопка уже есть в оболочке прода) и подложек зелёная; 2014 не сломан.
- Тестер: кадры кабинета «Оформление» 1440/390, свет/тьма, все 12 подложек хотя бы на витрине; чек-лист функций оформления с `origin/main`; автопроверка к20/фонов.

### Этап 2. Оболочка, авторизация, заглушка сайта, личный кабинет

- Читать: `SCREENS.md` разделы Б–Г (без списка персонажей как основного объёма — он в этапе 3, но оболочка списков уже живёт здесь), CONCEPT §18–§20, §27 по касанию опроса (опрос можно закрыть здесь же или стыком с кабинетом).
- Гость, вход, регистрация, Яндекс/VK, забыли пароль и связанные состояния; заглушка «Пока куются врата»; кабинет включая «Админку» только для админа и «Написать нам». Нижняя панель и боковое меню v2. Кубик C из общего файла.
- Критерии: все состояния §20 доступны; тексты с прода; функции прода на месте (чек-лист); нет дубля «войти» в одном контексте; автопроверка к20 и подложек; 390 и 360, свет/тьма.
- Тестер: отдельный чек-лист по каждому экрану авторизации и кабинета, сверка с `origin/main`.

### Этап 3. Мои персонажи (и список лобби v2 как страница оболочки)

- Читать: CONCEPT §15–§17, `SCREENS.md` Г.
- Крупные плитки — принятый вид; размеры, теги, «+», перетаскивание по гибриду. Список лобби v2 — это **список**, не хаб стола.
- Критерии: функции списка и тегов с прода не потеряны; бросок с этих страниц не пишется в журнал персонажа; кубик C; подложки с рисунком; плотность не ниже прода.
- Тестер: чек-лист + автопроверка к20/фонов + 1440/390/360 свет/тьма.

### Этап 4. ПК-лист (5 сцен и окна 9 шагов)

- Читать: `DECISIONS.md` §1–§9, `pc-sheet-buttons-prod.md`, `notes/sheet-inventory.json` (178 пунктов), `SCREENS.md` Ж. Эталон `sheet-desktop.html`.
- Шапку трогать очень аккуратно. 2014 не ломать. Журнал броска в панели кубика. Все окна на законных персонажах.
- Критерии: 178 пунктов на месте или явно сопоставлены с кодом прода; удаление без confirm; «к20»; книга только у волшебника; автопроверка к20/фонов; md5 `sheet-desktop.html` в репозитории концепта не изменён (в продукт переносится вид, файл концепта не переписывается).
- Тестер: полный чек-лист по сценам; регрессия 2014; кадры ключевых окон свет/тьма.

### Этап 5. Мобильный лист (9 шагов)

- Читать: `MOBILE-FINAL.md`, `DECISIONS.md` М.1–М.5, эталон `sheet-mobile.html`.
- Сцены не занимают место нижней панели приложения. Шторки поверх таб-бара. Кубик C в центре панели.
- Критерии: пять развилок 20.11 соблюдены; функции прода мобильного листа на месте; 390 и контроль 360; свет/тьма; автопроверка к20/фонов; 2014 цел.
- Тестер: чек-лист + сравнение с эталонными контактами `png/sheet-mobile/mobile-final-contact*.png`.

### Этап 6. Мастер создания (2014 и 2024, десктоп и телефон)

- Читать: `creation-plan.md`, `DECISIONS.md` С.1–С.17, BPMN Б.15–Б.17.
- Правило кликов, не предзаполнять осмысленный выбор. Кубик только C (после t927u).
- Критерии: шаги 1–12 покрыты; поля прода не упрощены; 2014 и 2024; 1440 и 390; автопроверка к20/фонов; чек-лист функций мастера с `origin/main`.
- Тестер: прогон форм 2014 и 2024, путь лобби, черновик, Готово.

### Этап 7. Классический лист и PDF

- Читать: `classic-handoff.md`, `DECISIONS.md` К.1–К.16, эталоны `png/classic/etalon-*`.
- Не менять генераторы эталона `html14()` / `html24()` в концепте. В продукте визуально совпасть с эталонными PNG, а не наоборот. PDF-сервис — контракт из handoff. Форма независима от редакции персонажа. Бумага не тёмная «тема листа».
- Критерии: diff с эталонными страницами; кегль 7–14 без обрезки на контрольных пресетах; имена PDF; напарники и death saves по правилу; настройки в `sheet.ui.classic_*` узким PATCH; автопроверка касается UI панели (к20/подложка оболочки), не рисунка бумаги.
- Тестер: 2014 и 2024, кросс-печать, бланк, 1440/390/360, свет/тьма панели.

### Этап 8. Справка v2 и окно броска v2 (финальная сверка)

Вёрстку этих окон допустимо сделать уже на этапе 2, потому что они живут в оболочке. Этот этап — обязательный тестер и добивка расхождений с §21–§22: тёмные и 390, журнал, преимущество/крит, тексты справки с прода. Автопроверка к20 (состояние «открыто») и подложек. Чек-лист функций. Не угадывать пробелы кадров — делать оба вида по правилу, если Игорь не скажет иначе (`SCREENS.md`, неясное п. 4).

### Этап 9. Лобби «Лобби / Стол / Мир» — только после приёмки макетов

Не начинать внедрение, пока Игорь не примет макеты шагов лобби. Тогда: `lobby-plan.md`, BPMN, связь с листом как ключевая фишка, инициатива строкой, мир по местам. К20 и подложки снова только из общего файла. Отдельный тестер, полный чек-лист, автопроверка, роли мастер/игрок.
