## Как читать пакет

Читать в таком порядке:

1. Этот `README.md` — цель, состав, как не потерять экраны.
2. `RULES.md` — жёсткие правила, в начале — главное правило проверки каждого этапа (22.11.2026, 10:01). Действуют на каждом этапе, даже если в задании этапа они не повторены.
3. `CHECKLIST-FUNCTIONS.md` — шаблон чек-листа этапа: перенос функций прода, двойные пути, логика, 2014. Тестер заполняет его отдельно по каждому этапу.
4. `SCREENS.md` — полный реестр экранов, окон и состояний со статусом и доказательством утверждения. Сначала сверить с контакт-листами. Список «не утверждено / неясно» — в конце, ничего из него не додумывать.
5. `DICE.md` — единое правило утверждённого кубика C. В производстве везде только он, даже если на старом макете другой знак или кубика нет.
6. `BACKGROUNDS.md` — подложки, дефолты, правило «рисунок только на холсте».
7. `UIKIT.md` — токены, шапка, нижняя панель, кнопки, модалки, шрифты, акценты. Стили только из UI-кита.
8. `ETALONS.md` — эталоны, md5, как сверять, что нельзя менять.
9. `PROJECT-BRIEF.md` — готовый текст задания проекту: этапы, критерии приёмки, тестеры, путь в репо, что класть в PR.

Дополнительно:

- `catalog/concept-all-pages.json` — оглавление 145 страниц `kried20-concept-all.html` (метаданные без встроенного HTML).
- `contact-sheets/` — 3 страницы обзора утверждённых экранов, чтобы глазами проверить полноту.
- `FILEMAP.md` — что лежит в архиве и где на диске полные эталонные PNG (они тяжелее гигабайта, в zip входят не все промежуточные кадры).

Исходный журнал решений и описания — в родительской папке концепта: `CONCEPT.md`, `DECISIONS.md`, `PRODUCTION-PLAN.md`, `DICE-ICON.md`, `MOBILE-FINAL.md`, `creation-plan.md`, `classic-plan.md`, `classic-handoff.md`, `lobby-plan.md`, `bpmn/`. ## Важное про кубик и подложки

Утверждённый кубик C и 12 подложек есть **не на всех старых кадрах**, а в части новых макетов снова оказывались не тот знак и фон без рисунка. Правило с 22.11.2026, 10:02: к20 и подложки берутся **только из** `css/shared-approved.css` и не рисуются заново; кадры каждого этапа проходят автопроверку против эталона, иначе тестер отклоняет этап. Подробности — `DICE.md`, `BACKGROUNDS.md`, `RULES.md`. Принятые старые кадры концепта задним числом не перерисовывать.
