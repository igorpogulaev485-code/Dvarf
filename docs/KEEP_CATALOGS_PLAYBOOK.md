# creed20 — как сохранить справочники и снизить юридический риск

> Позиция продукта: **справочники не выкидываем.**  
> Задача — не «можно ли иметь PHB/MPMM/бестиарий», а **какой стек щитов делает хранение защищаемым** и от WotC, и от претензий РФ-площадок (ttg / dnd.su / LSS).
>
> Это playbook стратегии, не заключение адвоката. Перед монетизацией — короткая сверка оферты с IP-юристом.

Связано: [`GTM_STRATEGY_PLAN.md`](GTM_STRATEGY_PLAN.md) · [`PRODUCT_PHILOSOPHY.md`](PRODUCT_PHILOSOPHY.md) · аудиты на tip (`RACES_AUDIT_2014.md`, `BESTIARY_AUDIT_2014.md`).

---

## 0. Исходный факт (зачем щиты)

На прод-линии каталоги уже большие и **осознанно** собраны из экосистемы ttg.club / dnd.su (см. аудиты рас и бестиария: «источник правды — ttg / dnd.su»).

Это **два** разных риска:

| Риск | Кто | О чём |
| --- | --- | --- |
| **A. IP правообладателя** | Wizards of the Coast | Тексты/сущности официальных книг вне SRD |
| **B. Зеркало РФ-справочника** | ttg / dnd.su (и репутационно LSS) | Копирование *их* базы, API, карточек, уникальной вёрстки/структуры → «плагиат» / недобросовестная конкуренция / ToS |

Отказ от справочников снимает оба риска ценой продукта.  
Наш путь: **оставить справочники**, но **сломать риск B** и **упаковать риск A** режимом, который индустрия уже использует.

---

## 1. Целевой режим (одна фраза)

**Справочники остаются в продукте навсегда и бесплатно.  
Деньги — только за creed20-инструмент (стол, лист, жесты, облако).  
Данные перестают быть «зеркалом ttg» и становятся «community reference layer» с дисклеймером.**

Это не режим «выкинуть PHB». Это режим «переупаковать PHB так, чтобы претензию было трудно обосновать и невыгодно открывать».

## 2. Стек щитов (как «нельзя» → «можно оставить»)

Щиты работают **вместе**. Один щит = дырка.

### Щит 1 — Firewall монетизации (жёсткое правило)

| Можно брать деньги за | Нельзя брать деньги за |
| --- | --- |
| Play Desk, облако, шаринг, лимиты персонажей/лобби, PDF-UX, интеграции, приоритет поддержки | Доступ к справочникам, «разблокировку книг», подписку «весь PHB» |

**Зачем:**  
- Ближе к **Fan Content Policy** WotC (фан-контент с IP — бесплатный доступ; донаты/реклама/спонсоры ок; продажа самого фан-контента — нет).  
- Совпадает с практикой **LSS** (инструмент + поддержка, а не витрина книг).  
- Убивает главный мотив претензии: «вы торгуете нашей IP».

**Превращение:** «нельзя продавать книги WotC» → «можно продавать iPhone-жесты creed20, пока каталог бесплатен».

### Щит 2 — Разрыв происхождения от ttg / dnd.su (главный РФ-риск)

Сейчас SoT в доках = ttg/dnd.su. Это самая быстрая дорога к претензии **именно из РФ**.

| Делаем | Не делаем |
| --- | --- |
| Фиксируем SoT: **официально изданные книги + собственная структуризация** | Live-парсинг API ttg / HTML dnd.su |
| Убираем публичные `external_ref` на dnd.su/ttg из API/UI | Рекламу «мы как dnd.su, только…» |
| Свой schema / slug / UX карточек (уже свой продукт — держать) | Копирование вёрстки/кода LSS или карточек ttg |
| Внутренний журнал «книга → страница → поле» у команды | Публичные коммиты «скрапнули ttg» |

**Превращение:** «нельзя быть зеркалом ttg» → «можно иметь тот же *игровой* охват как **своя** компиляция для стола».

> Практический смысл: претензия «вы украли нашу БД» ломается, если у вас иная структура, иные формулировки и нет следа выгрузки. Претензия «у вас эльф из PHB» — уже риск A, его закрывают щиты 1/3/4.

### Щит 3 — Форма контента: механика + свой короткий RU

Авторское право сильнее бьёт по **дословному художественному/правильному тексту**, слабее — по **фактам/числам/структурированным параметрам** (хотя «правила игр» — серая зона, не серебряная пуля).

| Слой данных | Политика хранения |
| --- | --- |
| Числа и механика (КД, скорость, CR, слоты, компоненты, формулы листа) | **Оставляем** — это топливо жестов creed20 |
| Короткие trait-блобы на своём RU | **Оставляем / переписываем** своим языком |
| Длинные дословные описания «как в книге / как на dnd.su» | **Переписываем** или выносим в optional full-text (см. щит 5) |
| Официальный арт WotC | **Никогда** |
| Имена сущностей (расы, заклинания, монстры) | Оставляем как идентификаторы стола + дисклеймер |

**Превращение:** «нельзя выложить PHB целиком текстом» → «можно держать playable reference, на котором строится клик до приключения».

### Щит 4 — Юридическая упаковка продукта

Обязательный пакет до публичного анонса / $:

1. Страница `/legal` (или `/about/legal`):
   - атрибуция **SRD 5.1 / 5.2.1** (CC-BY-4.0) для SRD-слоя;
   - для community-слоя — формулировка в духе Fan Content: неофициально, не endorsed by Wizards, © Wizards на их материалы;
   - явно: **справочники бесплатны**; платные опции = сервис creed20.
2. Политика UGC / импорта: пользователь отвечает за то, что заливает.
3. Контакт notice-and-takedown (email) + процедура снятия карточки.
4. Бренд **creed20** без логотипов D&D / без «официальный».
5. Оферта и 152-ФЗ (РФ-хостинг уже есть).

**Превращение:** «серый сайт без лица» → «продукт с понятным режимом и кнопкой takedown» (так отвечают взрослые площадки).

### Щит 5 — Усиление (фаза 2, если нужно ещё жёстче)

Каталоги **не удаляем**; меняем *доступ к полному тексту*:

| Вариант | Суть | Когда |
| --- | --- | --- |
| **5a. Attestation** | Механика доступна всем; полный prose-pack книги X — после чекбокса «у меня есть книга X» | Если хотите сильнее отделить «раздачу текста» |
| **5b. Offline packs** | В репо/сервере — schema + importer; тяжёлые prose-пакеты ставит пользователь файлом | Если давление по prose |
| **5c. Community mirror opt-in** | Справочник как отдельный free community module, инструмент — core product | Если разводим юрлица/домены |

**Сейчас (фаза 1) 5a–5c не обязательны**, если закрыты щиты 1–4. Это запасные рычаги, не отказ от каталогов.

### Щит 6 — Операционный профиль РФ

- Хостинг и ПДн в РФ — уже в плюс.
- PR: creed20 = стол/лист/клик, **не** «лучший клон dnd.su».
- Не провоцировать LSS копированием UI/формул (философия iPhone vs Android уже канон).
- Не обещать «полный легальный PHB от WotC».

## 3. Слои данных в продукте (как жить с полным каталогом)

Каждая сущность в БД получает `content_layer`:

| Layer | Что внутри | Доступ | Деньги | Лицензионный ярлык |
| --- | --- | --- | --- | --- |
| `srd` | То, что реально в SRD 5.1/5.2.1 | Публично | Нет | CC-BY + атрибуция |
| `community_ref` | Официальные книги вне SRD (PHB+, бестиарий книг, MPMM…) | **Бесплатно всегда** | Нет | Fan Content / community reference + дисклеймер |
| `user_import` | Импорт игрока / мастера | Только его аккаунт / стол | Нет | Ответственность пользователя |
| `homebrew` | Свой/коммьюнити хоумбрю | По правилам UGC | Нет | Лицензия автора |

**Каталоги, от которых вы не отказываетесь = `community_ref`.**  
Они остаются. Меняется упаковка и происхождение, не факт наличия.

## 4. Что это даёт против конкретных угроз

| Угроза | Как отвечает стек |
| --- | --- |
| WotC: «продаёте наш контент» | Щит 1 — не продаём |
| WotC: «дословная книга на сайте» | Щит 3 + 4; при эскалации щит 5 |
| WotC: «используете бренд D&D» | creed20 + дисклеймер, без логотипов |
| ttg/dnd.su: «украли нашу БД/API» | Щит 2 — разрыв происхождения, свой schema, без парсинга |
| LSS: «скопировали продукт» | Свой код/UI; не formula engine; другое кредо |
| Пользователь: «где мой PHB?» | Каталог на месте, бесплатно, жесты creed20 |

## 5. План внедрения (B0 → …) — без вырезания каталогов

### B0 — Инвентаризация (сейчас)

Не «что удалить», а **что как пометить и чем прикрыть**:

1. Матрица сущностей: `kind` × `source_book` × `content_layer` × `provenance` (`book_owned` / `legacy_ttg_mirror` / `srd` / `user`).
2. Список полей: `mechanics` vs `long_prose` vs `art`.
3. Найти и пометить все `external_ref` на dnd.su/ttg.
4. Критерий готовности B0: 0 «неизвестно»; есть объём `community_ref` (ожидаемо большой — это ок).

### B1 — Упаковка

1. `/legal` + атрибуция SRD + Fan Content / community disclaimer.
2. В продукте: бейдж/сноска «неофициально · справочник бесплатен».
3. Запрет paywall на `community_ref` в коде и в оферте.
4. Takedown-процедура.

### B2 — Анти-зеркало

1. Выключить любые пайплайны fetch к ttg/dnd.su.
2. Доки аудита: SoT = книги + наша структура (ttg/dnd.su — только исторический gap-check, не SoT продукта).
3. По возможности: проход перефраза long_prose на своём RU (волнами, начиная с самых «книжных» описаний).

### B3 — Монетизация

Включается **только** после щитов 1+4.  
Цены = desk/cloud/limits, никогда = «книга».

## 6. Решение по умолчанию (фиксируем)

| Вопрос | Ответ |
| --- | --- |
| Отказываемся от справочников? | **Нет** |
| Какой режим? | **Community reference бесплатно + $ за инструмент** |
| SRD-only как у урезанного LSS? | **Нет как стратегия продукта**; SRD — нижний слой, не потолок |
| Что делать с наследием ttg/dnd.su? | **Разрыв происхождения** (щит 2), не удаление охвата |
| Когда щит 5 (attestation/packs)? | Только если фазы 1–4 мало при реальном давлении |

## 7. Следующий конкретный шаг

Запускаем **B0-матрицу** на tip-каталогах:
