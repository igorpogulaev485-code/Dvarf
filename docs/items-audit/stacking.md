# Сложение эффектов предметов, правила 2014 и код

Страницы — английское издание PHB/DMG 2014 (нумерация русской книги другая). Код — лист Play Desk, если не сказано иначе.

## Правила, на которые опирается сверка

**Один расчёт КД.** Если способов посчитать КД несколько (доспех, природный доспех, защита без доспехов варвара или монаха), персонаж пользуется одним. Щит прибавляется к выбранному расчёту, когда его можно нести. PHB, Armor Class, стр. 144.

**Разные магические эффекты складываются, один и тот же — нет.** Пока длятся разные заклинания, их эффекты складываются. Повтор того же заклинания не складывается: берётся более сильный. PHB, Combining Magical Effects, стр. 205. Тот же принцип для одинаковых магических эффектов предметов: два независимых источника бонуса (кольцо защиты и плащ защиты) складываются; вторая копия того же предмета не должна давать второй бонус.

**Настройка.** Не больше трёх предметов одновременно. Нельзя настроить две копии одного предмета (пример из книги — два кольца защиты). DMG, Attunement, стр. 138.

**Что можно надеть.** Обычно одна пара обуви, одна пара перчаток, один плащ, один доспех, одна мантия. Колец — два. DMG, Wearing and Wielding Items, стр. 140–141.

**Фиксированное значение характеристики.** Перчатки огров: Сила становится 19, если сейчас не выше. Пояс великана задаёт своё число по тому же правилу. Два таких эффекта не суммируются. Если один предмет задаёт число, а другой даёт бонус «+2 к Силе», в книге нет отдельной формулы порядка. Нужно решение владельца (ниже).

**Изобретатель.** С 10 уровня настраивает четыре предмета, дальше пять и шесть (TCE, Magic Item Adept / Savant / Master). В данных класса адепт уже описан как «до 4» (`backend/data/classes/features/artificer_2014.json`).

## Как складывает Creed20

| Правило | В коде |
| --- | --- |
| Одна формула КД, затем щит | `computeArmorClass` (`frontend/src/shared/dnd/armor.ts`): доспех, иначе природный доспех, иначе защита без доспехов, иначе 10+Лов. Щит прибавляется один раз. |
| Плоский бонус КД разных предметов | `gearEffects.acBonus` — сумма всех `ac_bonus`. Кольцо +1 и плащ +1 дают +2. Это верно. |
| Условный бонус КД | Не отсекается. Наручи защиты дают +2 и в латах (баг I10 в `bugs.md`). |
| Спасброски с предметов | `save_bonus` суммируется, в том числе `all` на каждый спас. Кольцо и плащ складываются. Бросок с кнопки колонки характеристик это число включает. Отдельного броска концентрации с этим бонусом нет: диалог только спрашивает, удержал ли игрок. |
| Атака и урон оружия | Бонусы копятся по id строки и попадают в карточку атаки, пока оружие экипировано. Два разных магических оружия не бьют одним ударом: в руках одно (слоты рук в `heldEquip.ts`). |
| Бонус заклинаниям | Все `spellcasting_bonus` суммируются в одно число и вешаются и на атаку, и на СЛ. Два разных предмета сложатся. В диалог каста сумма не доходит (I01). Предметы, у которых бонус только в тексте, не входят в сумму (I18). |
| Фикс. характеристика | Последняя строка инвентаря затирает значение, даже если оно ниже своего. Потом все `ability_mod` прибавляются. Инфузии, в отличие от предметов, делают пол: поднимают, не опускают (`applyInfusionAbilityFloors`). |
| Навык | `skill_bonus` суммируется в колонке. Пассивки и чипы режимов этот бонус и новую характеристику не берут (I02). |
| Скорость | Дельты футов суммируются. |
| Чувства | По каждому чувству берётся максимум дистанции, не сумма. Тёмное зрение с расы и с предмета тоже через максимум. |
| Ячейки | Дельты `spell_slots` суммируются по кругу и пишутся в максимум ячеек (`syncGearGrantSpells`). |
| Заряды | Каждый предмет заводит свой пул. Одинаковые пулы двух предметов не сливаются и не запрещаются. Восстановление «на рассвете» записано как длинный отдых (I12). |
| Сопротивление | Тип есть в данных, в сумму урона не входит (I04). Два сопротивления одному типу по правилам не складываются в иммунитет; проверять не на чем, пока эффекта нет. |
| Лимит 3 настройки | Жёсткий потолок, в том числе у изобретателя (I05). |
| Вторая копия того же предмета | Не запрещена. Два кольца защиты можно настроить, если хватает слотов колец (их два) и лимита 3. Оба +1 КД сложатся. DMG стр. 138 это запрещает. |
| Слоты одежды | Один плащ, один доспех, два кольца (`wearEquip.ts`). Это совпадает со стр. 140–141. |

Ручные линии модификаторов листа (`draft.modifiers`, операция `+` или `=`) считаются отдельно, уже после предметов. `=` затирает накопленное число и дальше снова складывается (`applyBonusStack` в `modifiers.ts`). Это бонусы игрока, не каталог.

## Нужно решение владельца

1. **Фикс. значение и бонус «+N» вместе.** Варианты: (а) оставить как сейчас — последнее фикс. значение, затем сумма `ability_mod`; (б) фикс. значение не ниже своего счёта, бонусы «+N» после него; (в) из всех фикс. значений брать максимум и не складывать с `ability_mod` того же предмета. Инфузии уже живут по варианту «не ниже своего».

2. **Вторая копия одного предмета.** Варианты: (а) запретить вторую настройку того же slug/имени; (б) разрешить, но не складывать одинаковый эффект; (в) оставить сумму, как сейчас.

3. **Оружие и доспех +1/+2/+3.** Варианты: (а) шаблон «длинный меч / латы», как сейчас; (б) бонус к уже надетой конкретной вещи. От этого зависит, сложатся ли «латы» и «доспех +1» в один расчёт КД.

4. **Посох силы и посох магов.** Привести данные к DMG (у магов убрать КД и спасброски, атаку заклинанием вынести из `attack_bonus`) или сознательно оставить упрощённую карточку.

5. **Лимит настройки изобретателя** делать вместе с предметами или отдельной пачкой классов. Сейчас черта в тексте, слотов по-прежнему три.

6. **Свежая база.** Архивные миграции каталога не на пути Alembic. Либо идемпотентный upsert JSON от текущего head, либо считаем сид только продом.

7. **14 строк без карточки 5e14** (список в `count.md`): оставить как домашние/сеттинговые, переименовать под карточку сайта или выключить.
