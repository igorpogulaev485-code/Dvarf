# Каталог предметов

Как поправить справочник так, чтобы правка доехала и до пустой базы, и до уже выданных предметов.

## Как добавить или исправить предмет

1. Правь JSON в `backend/data/srd/2014/`. Новая порция — отдельный `gear_<имя>_v1.json` с ключами `inserts`, `updates`, `renames`, `deactivate_slugs`. Существующая строка — `updates` по `(kind, slug)` либо в своей волне, либо в новом файле.
2. Добавь файл в конец `GEAR_CATALOG_WAVES` в `backend/app/services/gear_catalog_seed.py`. Порядок волн — как в [`count.md`](count.md), раздел «Откуда цифры»: каждая следующая волна перезаписывает только те поля и ключи `data`, которые в ней есть. Ключи `data`, которых в JSON нет, у живой строки сохраняются.
3. Не меняй `id` уже существующей строки. Slug тоже не меняй, если на него ссылаются листы: для переименования есть `renames`. Удалять строки нельзя. Скрыть предмет — `is_active: false` в JSON или `deactivate_slugs`.
4. Новая миграция Alembic от текущей единственной головы вызывает `apply_gear_catalog_waves`. Если менялись правила (эффекты, настройка, слот, заряды, свойства доспеха), та же миграция вызывает `refresh_inventory_from_catalog`.
5. Повторный вызов обоих хелперов должен дать 0 изменений.

`catalog.json` — базовый SRD. Хелпер берёт из него только `item`, `weapon` и `armor`. Классы, подклассы, заклинания и остальные виды не трогает.

## Что обновляется у уже выданных предметов

`refresh_inventory_from_catalog` идёт по всем персонажам. Строка инвентаря с `catalog_id` получает из каталога `effects`, `requires_attunement`, `wear_slot`, свойства доспеха (`armor_kind`, `base_ac`, `max_dex_bonus`, `strength_requirement`) и ключи требований настройки (`attunement_*`, когда они появятся). Если `catalog_id` не находится, берётся `catalog_slug`, но только когда он указывает ровно на одну строку.

Не меняются: имя строки, количество, заметки, «надето», контейнер (`parent_id`), привязка слота настройки, атаки оружия, выбранное заклинание свитка (`scroll_spell`) и имя «Свиток: …». Текущие заряды не пополняются. Если новый максимум меньше остатка, остаток обрезается до максимума. Строка без `catalog_id` не трогается.

Записи справочника через API не пишутся: есть только чтение `GET /catalog`. Ручная правка строки прямо в базе переживёт сид только в тех ключах `data`, которых нет в JSON. Поля, которые JSON присылает (имя, источник, `effects`, `is_active` и остальные ключи `data`), сид выставит как в JSON. Поэтому выключенную в JSON строку сид снова не включит, а строку с `"is_active": true` включит, даже если её выключили вручную в SQL.
