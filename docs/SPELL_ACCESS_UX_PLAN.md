## 1. Зачем этот план

Сейчас у кастера **два дома** для одной задачи:

| Экран | Что умеет |
|-------|-----------|
| **Гримуар** | Каталог, описания, фильтры, «На лист» / «Подготовить» / «В книгу», кастом |
| **Подготовить** | «Подготовленные» / «Все доступные», лимит, снять/поставить |

После слайса «список класса в Все доступные» для жреца пути **пересеклись**: одно и то же заклинание можно подготовить и там, и там. Текст гримуара («сначала На лист → потом Все доступные») устарел.

**Цель продукта:** один главный экран — **Гримуар** (там детали и описания). Подготовка / изучение — действия *внутри* него. Отдельная кнопка «Подготовить» не исчезает сразу, но её роль сужается и становится честной.

**Для игрока:** не думать «куда идти учить / готовить».  
**Для агентов:** один контракт режимов, без второго источника правды по пулу.

## 2. Три механики (правила 2014) → три режима UI

Уже есть в коде: `SpellLearnModeUi` = `prepared_list` | `known` | `spellbook` (`spellAccessUi.ts`).

### 2.1. `prepared_list` — жрец, друид, паладин, изобретатель

| Правило | Следствие для UI |
|---------|------------------|
| Список класса известен целиком (до уровня ячеек *этого* класса) | Не «учить» из каталога; показывать список класса сразу |
| Готовит N заклинаний на день (лимит от класса + хар-ки) | Действие: Подготовить / Убрать |
| Смена набора — обычно после длинного отдыха (мы не таймерим отдых жёстко) | Игрок сам жмёт Убрать/Подготовить; лимит остаётся |

**Почему гримуар главный:** нужны карточки заклинаний (школа, компоненты, текст). Prepare-диалог сейчас беднее описаниями.

**Что уже сделано (оставить, перенести точку входа):**  
`prepareAvailability.ts` — union списков класса с *alone max level* (правильно для мультикласса). Сейчас это живёт в Prepare; должно питаться **гримуар**.

### 2.2. `known` — бард, чародей, колдун, следопыт (2014)

| Правило | Следствие для UI |
|---------|------------------|
| Мало «известных»; нет ежедневной подготовки списка класса | Действие = **выучить** (и редко — заменить при level-up) |
| Известное = готово к бою | Нет отдельного «сегодняшнего набора» |

**UI-упрощение (как предложил Игорь):** один расклад кнопок, как у жреца, но:

- подпись действия по режиму: **«Выучить»** / **«Забыть»** (предпочтительно)  
  *или* оставить слово «Подготовить», если боимся двух словарей — тогда обязательна одна строка-подсказка: «у known выучить = всегда с собой»;
- снятие ≠ «убрать на сегодня»: это потеря слота знания → confirm + уважение к правилам замены (level-up / рескилл).

**Почему не смешивать молча:** у жреца «Убрать» дёшево; у барда — дорого. Одинаковая кнопка без разных labels = баг продукта.

### 2.3. `spellbook` — волшебник

| Правило | Следствие для UI |
|---------|------------------|
| Сначала заклинание в **книге** (free / золото) | «В книгу» — обязательный шаг |
| Готовит из книги на день | «Подготовить» только из того, что в книге |
| Книга утеряна | Нельзя готовить новое; уже подготовленное остаётся |

**Поток:** Гримуар → «В книгу» → фильтр «В книге» → «Подготовить».  
Здесь отдельный быстрый экран «сегодняшний набор» полезнее всего (книга может быть длинной). Это не «только волшебнику», но **ему он нужнее**.

Спека: `wizard-spellbook.md` — не ломать.

## 3. Целевая модель экранов

### 3.1. Гримуар = единственный полный UI

**Всегда показывает:**

1. Поиск, уровень, книга-источник, класс.  
2. Карточку заклинания (описание, К/ритуал, компоненты).  
3. Статус относительно персонажа (чип): не на листе / в пуле / подготовлено / в книге / выучено / locked (домен и т.п.).  
4. Одно-два главных действия по режиму (таблица ниже).

**Новые (или явные) фильтры-чипы статуса:**

| Чип | `prepared_list` | `known` | `spellbook` |
|-----|-----------------|---------|-------------|
| Все доступные | Список класса до alone-max (+ раса/feat list) | Каталог класса (с бюджетом known) | Каталог для копирования в книгу |
| Подготовленные / Выученные | `prepared` | все known leveled | `prepared` из книги |
| Не подготовленные | в пуле/списке, но не сегодня | — | в книге, не подготовлено |
| В книге | — | — | `in_spellbook` |
| На листе вручную | кастом / вне списка | — | — |

«Все доступные» у жреца = **тот же смысл**, что мы уже заложили в Prepare, но **внутри гримуара**.

### 3.2. Действия по режиму (главные кнопки строки)

| Режим | Primary | Secondary | Опасное |
|-------|---------|-----------|---------|
| `prepared_list` | Подготовить / Убрать | (опц.) только «в пул» если когда-то нужно без prepare — **по умолчанию не нужно** | — |
| `known` | Выучить | — | Забыть (confirm) |
| `spellbook` | В книгу / В книгу + подготовить | Подготовить (если уже в книге) | — |

**Убрать у `prepared_list` кнопку «На лист» как основной путь** — она дублирует автосписок. Оставить только для: кастом, homebrew вне списка, заклинания не из class list (раса `spell_list` уже на листе через grants).

### 3.3. Кнопка «Подготовить» на листе / Play Desk

| Режим | Решение | Почему |
|-------|---------|--------|
| `prepared_list` | **Скрыть** или заменить на «Гримуар · подготовка» (открывает гримуар с чипом «Не подготовленные») | Дубль |
| `known` | Скрыть; вход = «Гримуар / Известные» | Нет daily prepare |
| `spellbook` | **Оставить** тонкий диалог «сегодняшний набор» (только книга, без полного каталога) | Длинная книга; быстрый morning prep |

Альтернатива (если Игорь хочет одну кнопку у всех): одна кнопка всегда открывает **Гримуар** с нужным чипом — тогда отдельный `PrepareSpellsDialog` удаляем целиком. Минус: волшебник листает каталог, если дефолтный чип не «В книге».

**Рекомендация плана:** гримуар главный для всех; `PrepareSpellsDialog` оставить **только** для `spellbook` (и временно как thin wrapper, который открывает тот же список, что фильтр «В книге»).

## 4. Что не ломаем (инварианты)

1. **Мультикласс prepare:** потолок уровня заклинания — по **каждому** классу *alone* (`maxSpellLevelForClassAlone`), не по общим ячейкам.  
   Гримуар сейчас местами режет по `highestSpellSlotLevel` (shared) — это **баг/расхождение**; в срезе 1 выровнять на alone-max для prepare-list membership.  
2. **Волшебник ≠ полный список wizard** в «доступных к подготовке».  
3. **Always-prepared** (домен, клятва, innate): нельзя снять; не едят лимит.  
4. **Лимит `max_prepared`:** кнопка Подготовить дизейблится / «Лимит».  
5. **Книга утеряна:** нельзя готовить новое.  
6. **Create pipeline / Level-up:** те же режимы и те же verbs.  
7. **Боевой список:** cantrips + подготовленные (или known-ready); виртуальные class-list строки **не** засоряют бой, пока не подготовлены.

## 5. Расхождение «сейчас» vs «цель» (честный аудит)

| Тема | Сейчас | Цель |
|------|--------|------|
| Главный экран деталей | Гримуар | Гримуар |
| Автосписок класса жреца | В Prepare «Все доступные» | В Гримуаре «Все доступные» |
| «На лист» у жреца | Есть, как путь в пул | Убрать как основной путь |
| Текст `spellAccessUi` для prepared_list | Частично обновлён в Prepare; гримуар hint ещё про «На лист» | Один источник copy |
| Фильтр «Подготовленные» в гримуаре | Нет явного status-chip | Есть |
| Known: label кнопки | Часто «Добавить» / prepare-пути | «Выучить» / confirm «Забыть» |
| Prepare-кнопка на листе | У всех prepare-capable | Только wizard (или deep-link в гримуар) |
| Потолок уровня в гримуаре | Shared slots | Alone max для class-list membership |
| Двойная загрузка каталога | Prepare + Grimoire | Один loader / общий cache |

| Задача | Как | Почему |

**Приёмка:** жрец 5 открывает гримуар → видит 1–3 ур. жреца без ручного «На лист» → готовит до лимита → «Убрать» работает → в бою только подготовленные.

### Срез C — Known: те же кости, другие слова

| Задача | Как | Почему |

**Приёмка:** бард не видит «Все доступные = весь список барда»; видит каталог с лимитом known; выучил → сразу в бою.

| Задача | Как | Почему |

## 7. Мультикласс (явно)

Пример: **Жрец 3 / Волшебник 2**

| Пул | Откуда | Макс. уровень в пуле |
|-----|--------|----------------------|
| Жрец | class list cleric | alone: 2 (не «общие ячейки 2-го круга как будто жрец 5») |
| Волшебник | только книга | то, что переписано; готовит по лимиту wizard |

UI: в гримуаре можно показать секции «Жрец» / «Книга» или фильтр класса — но **не** смешивать «подготовить огненный шар из списка волшебника без книги».

Пример: **Жрец 3 / Паладин 6** — union двух class lists с разными alone-max (у обоих часто 2).

## 10. Критерий «готово» для всей линии

1. Жрец готовит **только** из гримуара (или deep-link в него); нет второго полного UI.  
2. Бард учит из гримуара; не путает с daily prepare.  
3. Волшебник: книга → подготовка; morning prep быстрый.  
4. Мультикласс alone-max везде одинаковый.  
5. Описания заклинаний не хуже, чем сейчас в гримуаре.  
6. PRODUCT_STATUS обновлён после деплоя; tip не затирает edge/alembic.
