### Онбординг и стратегия (зачем это важно)

Онбординг **не** юр.слайс и **не** энциклопедия. Это прямой moat «iPhone»: маршрут новичка до жеста, без PHB внутри тура.

| Ось | Влияние |
| --- | --- |
| **Миссия** («D&D простым») | ✅ Закрывает фидбек «круто, но ничего не понятно» |
| **vs LSS** | LSS ≈ рычаги/формулы для тех, кто уже знает; КриD20 ведёт абсолютного новичка жестами + пояснениями на касании |
| **vs Beyond** | Beyond продаёт книги; мы учим *инструмент*, каталог бесплатен |
| **vs dnd.su/ttg** | Они справочник; мы не конкурируем туром по правилам — только продукт + короткие термины |
| **B4 позиционирование** | Усиливает «до приключения — клик»; PR-однострочник можно опираться на welcome |
| **B3 монетизация** | Сильнее история «$ за удобство понимания/жестов», не за текст книг |
| **B5 / B7** | Закрытая бета с новичками реалистичнее; всё ещё нужны legal-пакет и честные обещания |
| **Щиты 1–2 / B2** | Не ломает: не ссылаемся на ttg/dnd.su, не учим «как на справочнике» |

**Не смешивать** с `GuidedWizard` / create-pipeline: те про *правила выборов* (expertise, ASI…); O0+O1 — про *понимание продукта и листа*.

### 4.1 Персональные данные (152-ФЗ) — что нужно для соответствия

> Не юр.заключение адвоката. Перед публичным анонсом / $ — короткая сверка с IP/ПДн-юристом.  
> Оператором ПДн становимся, как только есть регистрация / OAuth / email / cookies сессии.

**Что уже собираем (общие ПДн):** email, логин/OAuth (Яндекс, VK), сессии/cookies, IP/user-agent в логах, данные кабинета и листов, переписка на info@. Спецкатегории и биометрию **не** собираем — так и держать.

| # | Требование | Зачем | Статус creed20 |
| --- | --- | --- | --- |
| 1 | **Уведомление Роскомнадзора** (`pd.rkn.gov.ru`) до/как можно скорее после начала обработки | Ст. 22: реестр операторов; почти нет исключений для коммерческого сайта | ⏳ |
| 2 | **Локализация ПДн в РФ** (запись, хранение, бэкапы) | Ст. 18 ч. 5 (242-ФЗ): первичные БД граждан РФ — на территории РФ | 🟡 VPS Timeweb РФ ✅ · проверить, что бэкапы тоже в РФ |
| 3 | **Политика обработки ПДн** на сайте (отдельная страница или блок `/legal`) | Публичный документ: цели, состав, сроки, права субъекта, контакты | ⏳ сейчас только короткий `/legal` |
| 4 | **Согласие при регистрации / OAuth** (отдельный чекбокс, не «в оферте мелко») | Ст. 9: конкретное, информированное; ссылка на политику | ⏳ |
| 5 | **Cookie / аналитика** — баннер или пояснение, если не только строго необходимые | Сессия логина = обычно необходимо; сторонний трекинг — отдельное согласие | 🟡 сессии ок · стороннюю аналитику не тащить без согласия |
| 6 | **Права субъекта**: доступ, уточнение, удаление, отзыв согласия | Кнопка/почта info@ + процедура удаления аккаунта | 🟡 контакт ✅ · «удалить аккаунт» / срок ответа ⏳ |
| 7 | **Ответственный за организацию обработки ПДн** | ФИО/контакт в уведомлении РКН и в политике | ⏳ |
| 8 | **Договоры с обработчиками** (хостинг Timeweb, SMTP, OAuth-провайдеры) | Хостер ≠ оператор; нужен договор/оферта про обработку | 🟡 Timeweb/Яндекс/VK — проверить условия |
| 9 | **Трансграничная передача** — отдельное уведомление РКН + согласие | Google OAuth, зарубежная аналитика/почта/CDN с ПДн | ✅ сейчас Яндекс+VK (РФ) · ⏸ Google/TG — не включать без уведомления |
| 10 | **Меры защиты + реакцият утечки** | HTTPS ✅ · пароли/хеши · доступы · журнал · 24ч РКН / 72ч субъектам при утечке | 🟡 HTTPS есть · внутренний регламент инцидента ⏳ |
| 11 | **Локальные акты** (если ИП/ООО): приказ об ответственном, перечень ПДн, модель угроз по уровню | Для реестра и проверок | ⏳ после формы бизнеса |

**Минимум до открытой беты / PR:** пункты **1–4, 6, 9** (уведомление РКН · политика · согласие на входе · удаление/отзыв · не тащить Google без отдельного контура).  
**До монетизации ($):** + оферта, обработчики, регламент утечки, акты.

**Связь с очередью:** это часть щита 4 / B1, не отдельный «продуктовый» слайс. Код: страница политики + чекбокс согласия + delete-account; бумаги: РКН + тексты — делает Игорь/юрист, агент готовит черновики UI и `/legal`.
