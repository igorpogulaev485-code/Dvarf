# План слайса: SMTP → info@creed20.tech (Яндекс)

**Контур:** план → **твой ok** → правки → проверка письма → **твой ok** → прод (обновить `.env` на VPS)

---

## Цель

Все системные письма (регистрация / подтверждение email / сброс пароля / смена email) уходят **от `info@creed20.tech`**, а не с личной почты.

Сейчас в коде: `From` = `SMTP_FROM` или `SMTP_USER` из `/opt/dvarf/.env` на Timeweb.  
В примере окружения до сих пор указан **Mail.ru** — это наследие; живые секреты только на сервере.

---

## Что меняем

### A. На сервере (главное) — `/opt/dvarf/.env`

| Переменная | Новое значение |
| --- | --- |
| `SMTP_HOST` | `smtp.yandex.ru` |
| `SMTP_PORT` | `465` |
| `SMTP_USE_SSL` | `true` |
| `SMTP_USER` | `info@creed20.tech` |
| `SMTP_PASSWORD` | **пароль приложения** Яндекса (не обычный пароль входа, если включена 2FA) |
| `SMTP_FROM` | `КриD20 <info@creed20.tech>` (или просто `info@creed20.tech`) |

После правки `.env` — перезапуск backend-контейнера (через обычный deploy/`compose up`), чтобы подхватил env.

### B. В репо (без секретов)

- Обновить `.env.prod.example`: комментарии Mail.ru → Яндекс 360 / `info@creed20.tech`
- В `mail.py` тексты писем: **Dvarf → КриD20** (тема и тело) — заодно, раз трогаем почтовый контур
- Также обновить `CORS_ORIGINS` / `APP_PUBLIC_URL` в example на `https://creed20.tech` (фактически на проде — когда DNS/HTTPS готовы; в этом слайсе можно только example + комментарий)
- PRODUCT_STATUS после проверки на проде

### C. Что нужно от тебя до деплоя

1. В Яндекс 360 / Почте для `info@`: создать **пароль приложения** для почты (если есть 2FA) —  
   либо подтвердить, что для ящика организации достаточно обычного пароля SMTP (Яндекс часто требует «пароль приложения»).
2. Прислать пароль **только** как secret агента / вставить самому на VPS — **не в чат и не в git**.
3. Явное **ok** на этот слайс + потом **«залей»** / ok на правку `.env` на проде.

---

## Acceptance

1. Письмо «сброс пароля» или «регистрация» приходит пользователю, в поле От кого: **info@creed20.tech** (КриD20).
2. Личная почта в `SMTP_*` на проде больше не используется.
3. В git нет паролей; `.env.prod.example` описывает Яндекс.

## Скрины / доказательства

1. Скрин письма во входящих: заголовок From = info@creed20.tech  
2. (опц.) кусок логов backend без пароля: SMTP ok

## Вне скоупа

- Полный Legal shell `/legal` (отдельный слайс)
- Смена DNS/NS
- Ребрендинг всего UI

## Риск

Неверный SMTP_PASSWORD → регистрация/сброс пароля перестанут слать письма.  
Откат: вернуть старые SMTP_* в `.env` и перезапустить.
