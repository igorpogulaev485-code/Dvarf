# Мультикласс и магия — как это устроено для игрока

Документ для согласования UX / UI-кита.  
Правила: PHB 2014, глава «Мультиклассирование» → «Заклинания».  
Технический план срезов: [`MULTICLASS_SPELL_ABILITY_PLAN.md`](./MULTICLASS_SPELL_ABILITY_PLAN.md).

---

## Зачем меняем

Сейчас лист ведёт себя как будто у персонажа **одна** магия: одна «атака заклинанием», одна «Сл. спас.», один общий лимит заговоров.

У мультикласса это неверно. У Квакка (изобретатель + колдун) из‑за этого:

- атака считалась только по ИНТ;
- заговоры колдуна упирались в лимит изобретателя;
- набор колдуна нельзя было нормально выбрать.

Нужно, чтобы игрок **видел несколько магий на одном персонаже** и не думал о таблицах PHB в бою.

---

## Как говорят правила (кратко и по делу)

1. **Что умеешь** — считаешь **по каждому классу отдельно**, будто у тебя только он: известные барда по таблице барда, книга волшебника по волшебнику, known колдуна по колдуну.
2. **Каждое** известное или подготовленное заклинание **привязано к одному классу**. При касте берётся **характеристика этого класса** (и фокус этого класса).
3. **Ячейки** обычные — общие по таблице мультикласса. Их можно тратить на заклинания любого своего класса. У колдуна дополнительно **ячейки договора**; обычные и договорные взаимозаменяемы. Ячейка **не меняет** характеристику.
4. Правила **не требуют** брать одно и то же заклинание дважды, если оно есть в двух списках. Дважды — только если сам хочешь две привязки (редко нужно).

---

## Главная идея продукта одной фразой

> У тебя на листе несколько «полок магии» (по классам).  
> Заклинание лежит на одной полке → оттуда же берутся Сл и атака.  
> Ячейки — общий кошелёк (+ договор отдельно).  
> В бою ты жмёшь заклинание — цифры уже правильные.

---

## 1. Шапка заклинаний (стол и панель)

### Один кастер-класс
Как сейчас: одна пара **Сл. спас. / Атака**, мелкая подпись характеристики.

### Несколько классов, одна характеристика
Например бард + колдун (оба ХАР):  
одна карточка **ХАР — Сл … · атака …**  
Бюджеты знания при этом **разные** (см. ниже) — не сливаются в один пул.

### Несколько характеристик (главный кейс)
Например бард + волшебник + колдун → ИНТ и ХАР:

```
[ ИНТ  Сл 19  ·  +11 ]
[ ХАР  Сл 18  ·  +10 ]
```

Чипы окрашены цветами характеристик из UI-кита (ИНТ — чернила, ХАР — слива, МДР — листва…).

**Чего не делаем:** обязательный переключатель «сейчас кастую от ИНТ / от ХАР» перед каждым кастом. Это ломает бой. Шапка — справочник; истина — на строке заклинания.

На узком экране: до трёх чипов в ряд; если больше — «ещё».

---

## 2. Список заклинаний в бою

Каждая строка показывает:

- название;
- **чью** это магию (короткий badge: Бард / Визад / Колд / Изобр. …) и/или цветной pip характеристики;
- при наведении или в карточке каста — уже посчитанные **Сл и атака для этой строки**.

Нажал «Кастовать» → диалог сразу с правильными цифрами → выбираешь ячейку (обычную или договор, если есть) → готово.

**Пример Квакка**

| Заклинание | Badge | Цифры |
|------------|-------|-------|
| Заговор / спелл изобретателя | Изобретатель | ИНТ: Сл 19 · +11 |
| Эльдритч бласт / спелл колдуна | Колдун | ХАР: Сл 18 · +10 |

Слот 3-го круга из общих ячеек на колдунский спелл — всё равно **ХАР**.  
Ячейка договора на спелл изобретателя — всё равно **ИНТ**.

---

## 3. Одно и то же заклинание в двух списках классов

### Нужно ли выбирать дважды?

**Нет, не нужно.**  
Выбрал один раз в секции нужного класса — заклинание привязано к нему — кастуешь с его характеристикой.

### Какую характеристику использовать?

Ту, **через какой класс** заклинание попало на лист (как в PHB: *associated with one of your classes*).

Выбор делается **когда учишь / готовишь / кладёшь в книгу**, а не «какую хар-ку поставить» в момент атаки.

### Когда имеет смысл второй раз?

Только если хочешь **две привязки** (например готовить как жрец на МДР и отдельно держать как известное барда на ХАР). Тогда в гримуаре явное действие:  
«Уже на листе как Бард. Добавить ещё раз как Колдун?» — по умолчанию **Нет**.

Если на листе две версии — при касте короткий выбор:  
«Как бард (ХАР…)» / «Как волшебник (ИНТ…)».  
Без двух версий выбора нет.

---

## 4. Лимиты — отдельные карманы, не один общий

Сейчас баг: «заговоры 4/4 изобретателя» блокирует колдуна.

Будет:

| Карман | Пример Art 15 / Warlock 5 |
|--------|---------------------------|
| Заговоры изобретателя | 0/4 |
| Заговоры колдуна | 0/3 |
| Гримуар договора (Tome) | +3 **сверх** лимита колдуна |
| Известные колдуна | свой счётчик known |
| Подготовка изобретателя | свой max prepared |

Мета на столе — честно и читаемо, например:

`заг. 4/4 · 3/3`  
или сумма с раскрытием: `заг. 7/8` → тап → разбивка по классам.

**Подготовленные** жреца/изобретателя и **известные** барда/колдуна **не делят** один лимит.  
Книга волшебника — отдельный мир: сначала в книгу, потом подготовка из книги.

Заговоры Гримуара договора кастуются как магия **колдуна** (ХАР), даже если название взято из чужого списка — это способность колдуна, не «второй класс».

---

## 5. Гримуар — несколько полок, разные действия

Один экран, но **секции или фильтр по классу**, не одна свалка с одной кнопкой «Добавить».

| Полка | Режим | Главные действия |
|-------|--------|------------------|
| Жрец / друид / паладин / изобретатель | список класса, готовишь на день | Подготовить / Убрать |
| Бард / чародей / колдун / следопыт | мало известных | Выучить / Забыть (с подтверждением) |
| Волшебник | книга | В книгу → Подготовить из книги |

Почему разные слова: у жреца «Убрать» дёшево (на сегодня не готовлю); у барда «Забыть» дорого (теряешь слот знания). Одна кнопка «Подготовить» на всех — путаница.

Фильтр «Все» показывает смешанный список с badge класса.  
Лимиты и «какой максимальный круг доступен из списка класса» считаются **по уровню этого класса**, не «раз у меня общая ячейка 5-го — беру огненный шар из списка жреца 3».

---

## 6. Создание персонажа и level-up

Мастер больше не спрашивает один общий «выбери 4 заговора».

Вместо этого — **по классам**:

1. Заговоры и магия класса A (свой бюджет, свой список).  
2. То же для класса B, C.  
3. Если выбран Гримуар договора — отдельно три бонусных заговора.

Кнопка «Далее» блокируется только если не закрыт **текущий** класс, а не потому что чужой счётчик уже полный.

После создания на листе сразу видны правильные чипы Сл/атаки и заполненные полки без ручного «починить колдуна».

---

## 7. Стресс-кейс: бард + волшебник + колдун

Представь персонажа 20 уровня: Бард 6 / Волшебник 8 / Колдун 6.

**Что видишь в шапке**

- ИНТ — Сл и атака по интеллекту  
- ХАР — Сл и атака по харизме  

(Два чипа, не три: бард и колдун делят ХАР.)

**Что видишь в гримуаре**

- полка Бард — выучить/забыть, бюджет барда 6;  
- полка Волшебник — книга и подготовка, бюджет волшебника 8;  
- полка Колдун — выучить/забыть + ячейки договора, бюджет колдуна 6.

**В бою**

- песня барда → badge Бард → ХАР;  
- fireball из книги → badge Волшебник → ИНТ;  
- blast колдуна → badge Колдун → ХАР;  
- ячейку выбираешь любую подходящую (общую или договор).

**Одинаковое заклинание в списках барда и колдуна**  
Учил один раз у барда → одна строка, ХАР, бардовский.  
Второй раз не трогаешь, пока сам не захочешь вторую привязку.

---

## 8. Что игрок больше не должен делать руками

- Пересчитывать «эта атака +11, а эта +10».  
- Помнить, что слот договора не делает спелл «интеллектуальным».  
- Упираться в чужой лимит заговоров.  
- Искать, куда идти: «Подготовить» vs «Гримуар» vs «Известные» — у каждой полки свои честные кнопки.

---

## 9. Что остаётся простым для обычного персонажа

Один класс-кастер → один чип, один бюджет, привычный поток.  
Усложнение UI **только появляется**, когда на листе реально несколько кастер-классов или две характеристики. Моно-волшебник не должен чувствовать «мультиклассный» интерфейс.

---

## 10. Границы (чтобы не раздувать ожидания)

Эта доработка **не** чинит сама по себе:

- КД без доспехов, если при создании взяли золото вместо экипировки;  
- пустой блок атак без оружия в инвентаре.

Это отдельные темы снаряжения.

---

## 11. Ощущение «готово» для игрока

1. Открыл стол — вижу столько карточек силы магии, сколько **разных характеристик** у моих классов.  
2. В списке у каждого заклинания понятно, **чьё** оно и какие у него Сл/атака.  
3. Каст не спрашивает характеристику, если версия одна.  
4. Лимиты по классам не мешают друг другу; Tome не ест обычные заговоры колдуна.  
5. Одно имя в двух списках — выбираю один раз; второй раз только осознанно.  
6. Mono-кастер выглядит почти как сейчас.

Так UI-кит отражает правило PHB («заклинание ассоциировано с одним классом»), не заставляя игрока быть энциклопедией мультикласса.
