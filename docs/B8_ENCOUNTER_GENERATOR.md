# B8 — Умный генератор боёв (продуктовый каркас)

Статус: **дизайн + ядро бюджета/тем в коде · UI генератора не релизить, пока все сигналы листа учтены**  
Ветка: `cursor/session-b8-generator-bacd` ← `cursor/session-b7-encounters-bacd`

Код уже есть:
- `backend/app/dnd/encounter_budget.py` — пороги DMG + budget × party_power  
- `backend/app/dnd/encounter_themes.py` — мультивыбор тем + семейства  
- `backend/app/dnd/party_power.py` — формула множителя по агрегатам листа  
- `backend/app/dnd/sheet_signals.py` — парсер sheet → `PartyAnalysis` / anti-air  
- `backend/app/dnd/encounter_pool.py` — фильтр пула + кандидаты босса

- `backend/tests/test_encounter_budget.py`, `test_sheet_signals_and_pool.py`

## Проблема

dnd.su / сырой CR: «сложный» бой оказывается лёгким из‑за артефактов, расходников, способностей, заклинаний. Бюджет должен быть **честным под ярлык** (смертельный = смертельный).

## Жест мастера (1 экран)

1. Сложность → 2. Режим (сразу / волны) → 3. Локация → 4. **Тема/фракция** (мультивыбор + тумблер «похожие») → 5. Предложения (босс / пачка) → 6. «На стол» / в шаблон энкаунтера

## Входы

### Сложность (шкала продукта)

`Лёгкий | Средний | Сложный | Смертельный`

- Ярлык = реальный бюджет, без занижения.
- **Стартовая** формула бюджета: пороги XP из **DMG 2014** по уровням пати.
- Формула **точно изменится**: после разбора сигналов с листа пороги будут подниматься/сдвигаться (пати Игоря сейчас проходит «сложное» слишком легко).

### Режим

- **Сразу** — один блок «босс + пачка».
- **Волны** — N блоков «босс + пачка» (следующая волна = ещё один такой блок). Число волн без жёсткого лимита в продукте.

### Локация = `environment` бестиария

подземье · лес · город · горы · холмы · болото · равнина/луг · пустыня · побережье · полярная тундра · под водой · тропики · деревня · подземелья · руины · **любая**

### Тема / фракция (обязательный фильтр состава)

Мастер задаёт «кто это» — не только местность.

| Слой | Примеры | Источник в каталоге |
|------|---------|---------------------|
| Тип существа | нежить, исчадие, зверь, дракон… | `data.type_ru` / `type` |
| Подтип / племя | демоны, дьяволы, орки, гоблиноиды, кобольды, гноллы… | `data.subtype` |

**Мультивыбор** — несколько тем сразу (пример: орки + нежить; можно добавить демонов).  
Кандидат проходит, если попадает **хотя бы в одну** выбранную тему (OR).

**Тумблер «похожие»**
- **выкл** — только точное совпадение типа/подтипа;
- **вкл** — расширять каждую выбранную тему семейством (орк → гоблиноид/кобольд/гнолл; демон → другие fiend-подтипы и т.п.).

Чужие семейства не подмешиваются: если выбраны только орки и тумблер выкл — нежити в пуле нет; нежить появляется только если её явно отметили в мультивыборе.

### Пати — сигналы с листа (все must, релиз только когда все учтены)

- уровень, класс / подкласс  
- HP / КД  
- DPR (атаки, заклинания)  
- ресурсы (слоты, ярость, ki…)  
- магия / сопротивления  
- артефакты / расходники  
- напарники за столом  
- активные бафы на сессии  

Плюс анти-фейл: **летающие** (`speed.fly`) — не предлагать, если пати слабо против fly (нет надёжного ranged / своего fly / контроля высоты).

## Выход

- Роли: **босс** + **пачка** (не три роли волн).
- На роль: **2–3 кандидата** из бестиария; мастер выбирает.
- **Количество** в пачке считает продукт под бюджет сложности.
- Источник монстров: **только бестиарий** (не кастом-НПС лобби).
- Посадка: на стол сессии и/или сохранить как шаблон энкаунтера (B7).

## Закрыто по UX темы

- Мультивыбор тем (орки + нежить + демоны — ок).
- Тумблер «только точные / с похожими».

## A. Инвентаризация сигналов листа (факт кода)

Источник: `Character.sheet` JSONB + поля модели + seat/session combat.  
Релиз B8 **только** когда все строки ниже учтены алгоритмом (прямо или через явный прокси).

| Сигнал (продукт) | Где лежит сейчас | Качество для алгоритма | Пробел |
|------------------|------------------|------------------------|--------|
| Уровень | `Character.level`, `sheet.classes[].level` | ✅ | — |
| Класс / подкласс | `sheet.classes[]` (`name`, `subclass_name`, `catalog_id`) | ✅ | — |
| Раса | `Character.race_name`, `sheet.identity.race_catalog_id` | ✅ | — |
| HP текущие/макс | `Character.hp_current` / `hp_max` | ✅ | — |
| HP temp | `sheet.combat.hp_temp` | ✅ | — |
| КД | `sheet.combat.ac` (+ броня из inventory) | ✅ | — |
| Скорость | `sheet.combat.speed` | ✅ | — |
| Абилки | `sheet.abilities` | ✅ | — |
| Атаки / DPR оружие | `sheet.weapons[]`: `damage`, `damage_type`, `ability`, `source_kind` | ⚠️ строка урона | **нет range / melee|ranged** |
| Заклинания / DPR магия | `sheet.spells.known[]`: `damage`, `range`, `level`, `prepared` | ⚠️ парсить строки | — |
| Слоты | `sheet.spells.slots` 1–9 + `pact_slots` | ✅ | — |
| Ресурсы (ярость, ki…) | `sheet.resources[]`: `name`, `max`, `used`, `reset` | ⚠️ имена свободные | нужна нормализация имён |
| Концентрация | `sheet.combat.concentration` | ✅ | — |
| Активные бафы | `sheet.combat.effects[]` + seat на сессии | ✅ имя/связь Conc | нет механики «+к атаке» |
| Состояния | `sheet.combat.conditions[]` | ✅ | — |
| Напарники | `sheet.companions[]` / seat companions (HP, КД) | ✅ | тип (скакун/фамильяр) слабо |
| Артефакты (аттюн) | `sheet.attunements[]` (до 3 слотов, имя/notes) | ⚠️ | нет бонусов статов в структуре |
| Инвентарь / расходники | `sheet.inventory.items[]` (имя, qty, notes, armor) | ⚠️ | **нет kind=consumable/magic** |
| Монеты | `sheet.inventory.coins` | низкий приоритет | — |
| Сопр./иммун. ПК | — | ❌ | **нет на листе** → прокси: класс/раса/спеллы |
| Fly у пати | — | ❌ прямой | прокси: спелл `range`/`fly`, раса, ресурсы |
| Ranged у пати | — | ❌ флаг | прокси: `spells.range` + эвристика оружия (dex/название) |

### Вывод по данным

- **Ядро бюджета** (уровень, HP, КД, слоты, ресурсы, атаки.damage, спеллы, напарники, бафы-имена, аттюн-счётчик) — **уже читается**.
- Для релиза «всё учтено» нужно закрыть пробелы **прокси-слоем** (без ломки листа) или точечно дополнить схему:
  1. `weapons[].range_kind`: `melee | ranged | reach` (или парсер по каталогу оружия);
  2. тег расходника / магии на `inventory.items` **или** эвристика по `catalog_id`/имени (зелье, свиток…);
  3. вклад аттюна: пока множитель от **числа заполненных слотов** + эвристика по имени; позже — структурированные бонусы.

## C. Бюджет сложности (черновик алгоритма)

### C1. База DMG 2014

На каждого PC уровня L — порог XP сложности (easy/medium/hard/deadly) из таблицы DMG.  
`budget_base = Σ thresholds(level_i, difficulty)`.

Уже есть `backend/app/dnd/xp.py` (CR→XP). Пороги пати — добавить рядом (`XP_THRESHOLDS_BY_LEVEL`).

Множитель числа монстров DMG (1 / 2 / 3–6 / 7–10 / 11–14 / 15+) применяем к **трате** бюджета пачки, не к порогу.

### C2. Множитель пати `party_power` (поверх базы)

`budget = budget_base × party_power`, `party_power = clamp(0.85 … 2.2)`.

| Сигнал | Как влияет (черновик весов) |
|--------|-----------------------------|
| Средний уровень vs ожидание | уже в базе |
| Σ HP_max / ожидаемое по уровню | +0.05 за каждые +20% выше нормы |
| Средний КД vs норма уровня | +0.04 за +2 КД выше нормы |
| Слоты: сумма `max` уровней 1–9 | +0.03 за «богатую» кастерскую пати (порог TBD) |
| Ресурсы: Σ (max−used) «боевых» | +0.02…0.08 |
| Аттюн: число заполненных слотов | +0.04 за слот (0…3 на PC, среднее по пати) |
| Расходники (эвристика qty) | +0.02…0.06 |
| Напарники с HP | +0.05 за каждого боевого |
| Активные бафы на сессии | +0.03 если есть Conc-баф на ≥1 PC |
| DPR proxy: Σ ср. урона атак+кантрипов | +0.05…0.15 по квантилям |

Игорь: сырой DMG «сложный» для его пати лёгкий → целевой `party_power` на таких листах **> 1.3**. Веса калибруем eval-кейсами, не релизом «на глаз».

### C3. Распределение босс / пачка

- **Босс:** один (или 1 на волну), CR так чтобы `xp_boss ≈ 35–55%` бюджета волны.  
- **Пачка:** остаток бюджета → число × CR кандидата (с учётом множителя численности).  
- Волны: бюджет делится на N волн (равные доли v1); каждая волна = босс + пачка.

### C4. Анти-фейл: летающие

Если `party_anti_air == weak` → исключить монстров с `speed.fly` из предложений (и босс, и пачка).

`party_anti_air`:
- **ok**, если есть спелл с ranged damage / control и range ≥ 30 фт, или оружие с эвристикой ranged, или явный fly у PC/напарника;
- иначе **weak**.
