# Dvarf — сообщение для друзей

## Когда писать

Игорь просит **сообщение / пост / анонс для друзей** (часто «в нашем стандартном формате»).  
Это **не** PR-описание и **не** `PRODUCT_STATUS` — это готовый текст для чата с друзьями: гордый, конкретный, с цифрами и чеклистом.

Пиши **после** того, как слайс реально на проде (или явно сказано «как будто залили» / черновик). Цифры и tip — из живой проверки / `PRODUCT_STATUS.md`, не выдумывай.

## Триггерные фразы (распознавай сразу)

- «сделай сообщение для друзей»
- «пост для друзей»
- «анонс в стандартном формате»
- «как мы круто поработали» + просьба про друзей / чат
- ссылка на этот skill / «по dvarf-friends-announce»

## Жёсткие правила тона

1. Язык — **простой русский**, как для друга за столом, не для инженера.
2. **Функция → как работает → что получает игрок.** Не список файлов и не «зарефакторили JSONB».
3. Гордость ок; вода и корпоративный тон — нет.
4. Эмодзи — в духе шаблона (🔥 🌐 📊 🎮 🧪 ⚠️ 🏆), не россыпь случайных.
5. Один пост = **один слой продукта** (черты / заклинания / расы…), не мешанина всех агентов.
6. В конце — лёгкий вызов («кто первый…»), 1–2 конкретных действия в UI.
7. Честно пометь ограничения (⚠️) и что **не** в релизе (например 2024).
8. URL прода всегда: `http://201.34.132.252/`
9. Укажи **prod tip**, цепочку PR, alembic head — как в блоке «ЦИФРЫ».

## Обязательная структура (не ломай порядок)

Скопируй каркас и заполни. Секции с `###` ниже — заголовки **внутри поста** (эмодзи + CAPS), не markdown H2 в чате.

```text
🔥 DVARF × <ТЕМА РЕЛИЗА> — МЫ ЭТО СДЕЛАЛИ 🔥

<1–3 абзаца хука: что было больно «вручную» → что теперь на проде. Конкретно.>

🌐 http://201.34.132.252/

📊 ЦИФРЫ
🎒 1 линия · PR #<first> → #<last> · tip <branch-name>
📚 <главная метрика каталога / объёма>
 → <разбивка по книгам / волнам, если есть>
📖 книги: …
✍️ ~N строк данных (спеки / JSON)
🧠 ~N строк логики (модули / попапы / apply-revoke)
🗄️ alembic head на сервере: <rev> (кратко цепочка)
🧩 <ключевые механики / пикеры / режимы>
✨ <вторичные фичи одной строкой>
🎯 <самый «вау» кусок UX>
🔗 связи: <стыки с расой / классом / фоном / ASI…>

<одно предложение-тезис: «это не X, это Y»>

🎮 КАК ЭТО РАБОТАЕТ (коротко)
<5–8 буллетов: путь игрока по UI, без имён файлов>

🧪 ЧЕКЛИСТ ДЛЯ ТЕСТА
✅ <конкретный сценарий 1>
✅ …
✅ <revoke / tip не затёрли соседний контур>

⚠️ На что смотреть
• <известные дыры / динамика / не в релизе>
• Источник правды: ttg.club / dnd.su — кривое пишите со скрином

🏆 ИТОГО
<статус соседних слоёв: Расы ✅ · … · этот слой ✅>
Одна линия прода. Один tip. <одна фраза про создание персонажа / бой / стол.>

Кто первый <конкретное крутое действие> — тот легенда.
Кто <второе действие> — тот красавчик. 🦞⚔️📜
```

## Как собирать цифры

1. Tip / alembic / URL — из `PRODUCT_STATUS.md` **после** verify на сервере (или `curl /health` + psql count).
2. PR-диапазон — цепочка слайса на tip (не чужие открытые PR вне линии).
3. Каталог — `count(*)` на проде или спеки в `backend/data/…`.
4. LOC — ориентир `wc -l` по спекам + ключевым модулям; округляй («~2 800+»), не притворяйся аудитом.
5. Чеклист — сценарии, которые реально можно пройти на проде **сейчас**.

## Чего не делать

- Не подменять пост сухим changelog / списком коммитов.
- Не писать «на проде: да», если сервер не проверен (тогда пометь «черновик до залива»).
- Не тащить секреты, `.env`, внутренние пути агента.
- Не раздувать roadmap в пост — только ⚠️ «не в этом релизе».
- Не менять порядок секций и не выкидывать ЦИФРЫ / ЧЕКЛИСТ / ИТОГО.
