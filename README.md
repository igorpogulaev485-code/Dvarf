# Dvarf

Свой тулинг для DnD 5e (RU-first). LSS — только визуальный/IA-референс, не основа продукта.

Сейчас это локальный клиент: карточка и классический лист — одна сущность, плюс каркас стола.

## Как устроено

```text
Лобби (персонажи)
├── Сеттинг ──┬── Сессия
│             └── Сессия …
└── Сессия (ваншот, без сеттинга)
```

| Путь | Уровень | Что |
|---|---|---|
| `/` | **Лобби** | Ростер всех персонажей. Карточка + классический лист — один персонаж. |
| `/settings` | **Сеттинг** | Зона мастера / мир. Не обязателен для игры. |
| `/settings/:id` | **Сеттинг** | Заметки о мире + список сессий этого сеттинга. |
| `/sessions` | **Сессия** | Столы: ваншоты и сессии, привязанные к сеттингу. |
| `/sessions/:id` | **Сессия** | Фрейм стола: кто играет сегодня. Сюда позже придут бой и лут. |
| `/characters/:id` | Лист | Карточка персонажа |
| `/characters/:id/sheet` | Лист | Классический лист 2014 |

**Правила модели**

- Сессия — самостоятельная сущность. Join, состав «на этот раз», бой, лут живут в ней.
- `settingId` у сессии может быть `null` — это ваншот.
- У одного сеттинга может быть несколько сессий.
- Удаление сеттинга не убивает сессии: они становятся ваншотами.
- Персонажи живут в лобби; в сессию их сажают со стола. Удаление персонажа убирает его из сессий.
- Глобальной роли «мастер / игрок» нет. Мастер — контекст сеттинга/сессии (пока локально это вы).

У LSS «комната» ближе к **сессии**, не к сеттингу. Слово «фрейм пачки» = UI сессии.

Правки на листе и в карточке пишутся в один store (`localStorage`). Сеттинги и сессии — отдельно (`dvarf.table.v1`).

`rulesEdition` (правила) и `sheetLayout` (вёрстка) разделены: можно играть по 2014 на листе 2024.

## Очередь

Сделано в этом каркасе: лобби, сеттинг (заметки о мире), сессия с опциональной привязкой, фрейм состава.

Дальше по слайсам (план → ok → код):

1. Бой на сессии (инициатива, хиты стола)
2. Лут на сессии
3. QR / invite в сессию
4. Открыть сеттинг игрокам (сейчас это зона мастера)
