# Dvarf — план экосистемы (Лобби → Сессия → Сеттинг)

Документ собран по опросу Игоря (2026-10-15).  
**Статус:** ok по содержанию + дополнение UI kit / mobile.  
После ok на mobile-каркас сессии (§0.2) — режем слайсы и пишем код от **prod tip**.

Прод / домен уже есть: `Characters → Lobby → Setting? → Session (seats)`.  
Этот план наращивает «мясо» поверх каркаса, а не заменяет модель.

---

## 0. Принципы

| Принцип | Решение |
|---------|---------|
| Порядок фаз | **A Лобби → B Сессия → C Сеттинг** |
| Роли | Глобальной роли нет. **Мастер = owner лобби** |
| Офлайн-first | Продукт для живого стола; онлайн получается «бесплатно». Мастер и игроки должны уметь **вводить результаты физических кубов** |
| **UI kit** | Только наш кит (`frontend/src/ui/*`, токены `index.css`, `AppHeader`, паттерны play desk). LSS — IA/референс жестов, **не** визуальный клон (у нас светлая «пергаментная» тема, не тёмный Vortex) |
| **Mobile-first** | Каждый экран лобби/сессии проектируется сначала под телефон за столом; desktop — усиление, не «потом прикрутим» |
| Realtime | Моментальные обновления (WebSocket или SSE — выбор инженерии) |
| Не выкладывать сырое | Особенно бой: лучше дольше, но цельный контур |
| Видимость | Одно дерево настроек на **лобби**; все сессии наследуют |
| LSS-референс | «Комната» LSS ≈ наша **сессия**; хаб кампании ≈ наше **лобби** |
| Лор | = **Сеттинг** (одно имя) |

## 0.1 UI kit — жёсткие правила для агентов

Источник правды: prod tip → `frontend/src/ui/` + CSS-переменные в `frontend/src/index.css`.

| Использовать | Не делать |
|--------------|-----------|
| `Button` (`primary` / `secondary` / `ghost` / `danger`) | Свои кнопки «как в LSS» с другой геометрией/цветом |
| `Panel`, `Stack`, `Text`, `Field`, `Input`, `Dialog`, `Toast`, `EmptyState`, `NumberPadDialog` | Новые примитивы без нужды; дубли `div` с теми же ролями |
| Токены `--ink`, `--muted`, `--accent`, `--panel`, `--line`, `--danger`, `--success` | Тёмная тема / glow / «dashboard» ради похожести на скрины |
| `page page--app`, существующие header/nav паттерны | Отдельный chrome только для лобби |
| Паттерны play desk (режимы, компактные панели, bottom dialogs) | Карточки-«дашборд» с кучей бейджей в первом вьюпорте |

Новые компоненты для экосистемы (мини-карточка, лента событий, дерево видимости) — **собирать из кита** и класть рядом с фичей (`features/lobby/*`, `features/session/*`), при переиспользовании ≥2 раз — поднять в `ui/` или `shared/`.

Критерий приёмки слайса: экраны лобби/сессии **узнаваемы как Dvarf**, а не как порт LSS.

## 0.2 Mobile-first — IA по поверхностям

Контекст: мастер и игроки часто смотрят в телефон **за живым столом** (одна рука, яркий зал, быстрый жест).

### Лобби (телефон)
- Табы = **горизонтальный scroll-chip row** под шапкой (не 7 пунктов в бургере сразу; активный таб в зоне большого пальца).
- **Состав:** вертикальный список упрощённых карточек на всю ширину (не сетка 3×N).
- **Дневник / чаты / заметки:** лента на всю ширину + composer снизу (sticky); пагинация вверх.
- **Настройки видимости:** аккордеон секций, крупные тап-зоны; пресеты — wrap-ряд чипов.
- Desktop: табы могут стать top tabs / боковой nav; состав — сетка карточек.

### Сессия / стол (телефон) — критичный экран
Десктопный «карточки слева + лента справа» на 375px **не копировать один в один**.

Предлагаемый каркас (нужен ok):

| Зона | Поведение на mobile |
|------|---------------------|
| Шапка | Название сессии, код лобби (copy), бейдж письма мастеру |
| Переключатель | Чипы: **Стол** · **Лента** · **Бой** (позже) · **Ещё** (чат / быстрая заметка) |
| Стол | Вертикальный список полных карточек (+ напарник сразу под хозяином); у мастера — крупные hit-target вдохновения/состояний |
| Лента | Live-события + фильтр персонажей; ввод броска / физ. куба через `NumberPadDialog` или компактный composer |
| Чат / заметка | Bottom sheet поверх стола — **без смены URL**, игрок не «уходит» |

Desktop (≥900px): двухколоночный стол (карточки + лента), чат/заметка — сайдбар; тот же каркас, усиленный шириной.

### Жесты мастера на mobile
- Вдохновение: 1 тап на карточке.
- Состояние: тап → `Dialog` выбора.
- XP / лут / противники: из «Ещё» / панели боя — не засорять первую карточку.

### Критерий приёмки mobile
Каждый слайс A/B на ширине **~390px** (и 360px): читаемость, тап без зума, без горизонтального скролла страницы (допустим только у ряда чипов/табов).

## 1. Карта поверхностей

```text
Лобби (кампания)
├── Состав          — упрощённые мини-карточки участников
├── Дневник         — инструмент мастера (посты + закрытие сессий)
├── Заметки         — личные у игроков + общая доска пати
├── Чаты            — тематические каналы (создаёт любой) + письмо мастеру
├── Сессии          — список / создать / кто пришёл → вход в стол
├── Сеттинг         — вики мира (фаза C)
└── Настройки       — имя, видимость (дерево полей), опасная зона

Сессия / стол (живой стол)
├── Полные карточки по профилю видимости (+ напарники отдельными карточками)
├── Live-лента событий (как «История событий» LSS)
├── Лог бросков (отдельная сущность, фильтры по персонажам)
├── Сайдбар: чаты лобби + быстрая заметка (без ухода со страницы)
├── Панель мастера: вдохновение, состояния, XP, лут, бой…
└── Боевой контур: противники, энкаунтер, инициатива, генератор боёв
```

Маршруты: список сессий в лобби **и** живой стол `/sessions/:id` (вариант C).

## 2. Решения по опросу (зафиксировано)

### Лобби и карточки
- Табы старта: Состав · Дневник · Заметки · Чаты · Сессии · Сеттинг · Настройки (можно доправить позже).
- В лобби — **упрощённые** карточки; в сессии — **полные** по дереву видимости.
- Размер пати: **ориентир вёрстки ~8** игроков; реально бывает 3 / 4 / 6, запас до **10** (сетка 1→2→3→4 колонки).
- Видимость: **на всё лобби** (A). Дерево полей сразу (как LSS: личность, здоровье с «только цвет», прогрессия, характеристики, бой, магия, ресурсы, экономика + пресеты).
- «Глазами игрока» — превью для мастера (с референса LSS).

### Дневник и броски
- Одна цепочка жизни кампании, но **лог бросков ведётся отдельно**.
- В дневник лобби: **посты мастера** + при закрытии сессии — итог в дневник (вариант A). Сырой лог бросков остаётся в архиве сессии.
- Дневник пишет только мастер. Игроки — свои заметки, не дневник.
- Посты: текст, «глава», ссылка на страницу сеттинга; **картинки только по URL** (Pinterest и т.п.), без загрузки на наш диск.
- История **полная**, с пагинацией (не «последние 100»).
- Игроки видят чужие броски в live по настройке: Активно / Без бросков мастера / Выкл.

### Заметки и чаты
- У игрока: **личный блокнот** (много заметок) + **общая доска пати**.
- «Заметка на карточке персонажа» (бывший 15.1 C) — **не делаем**, пока не понадобится отдельно.
- Мастер видит общие + свои мастерские **и** личные заметки игроков.
- На сессии — **быстрая заметка** в сайдбаре.
- Каналы чата создаёт **любой**.
- **Письмо мастеру**: тикет «вопрос → ответ» с возможностью продолжить диалог; писать **везде** (лист / лобби / сессия); у мастера **бейдж с именем персонажа**.

### Сессия и мастер-действия
- Мастер из **состава лобби** (и позже со стола сессии) всегда может открыть карточку/лист любого участника — **только просмотр**, без редактирования (`can_edit=false`). Правки — только у владельца персонажа.
- Мастер создаёт сессию и **отмечает кто пришёл**.
- Урон/хиты отмечает **игрок** (мастер озвучивает вживую).
- **Вдохновение** — часто, много раз за сессию → быстрый жест на карточке, **без подтверждения**.
- **Состояния** — редко (~1 раз / 3 сессии), тоже без подтверждения.
- **XP**:
  - после боя — из данных бестиария, делится на участвовавших;
  - плюс ручная выдача: одному / части / всем, в т.ч. вне боя.
- **Лут**: находка отражается у игроков → они распределяют → OK → сразу в инвентарь выбранных. Проверки «восприятие 12/16/20 → разный лут» и индивидуальный/общий поиск — заложить в дизайн лута (не обязательно в первом боевом слайсе, но в модели учесть).

### Бой (фаза B, цельный контур)
- Сразу полный стол + противники + инициатива — не «половина продукта».
- Каталог: **загруженный бестиарий** + удобное создание своего НПС.
- Нужны **шаблоны энкаунтеров** и **умный генератор боёв** (см. §5) — отдельная тяжёлая подфаза.
- Инициатива: **смесь** — автобросок **или** ввод с физических кубов.
- ХП/видимость противников — часть того же дерева видимости.

### Напарники и эффекты на союзников
- Напарник — **отдельная мини-карточка** на сессии; видят союзники (по видимости).
- Баф/инфузия на союзника: источник правды — эффект на цели + запись у кастера; снятие у кастера/по длительности снимает у цели. **Must-have**, не откладывать «на потом после боя».

### Realtime
- Слайсы A1–A2 (хаб, состав, настройки, создание сессии) можно без realtime.
- С **A3 (живой стол)** — realtime обязателен.
- Транспорт: без предпочтений продукта (WS/SSE — на команду).

## 3. Фаза A — Лобби (первый код после ok)

Цель: кампанийный хаб + вход в стол с live-лентой и бросками. Без полного боевого генератора.

| Слайс | Содержание | Realtime | Зависимости |
|-------|------------|----------|-------------|
| **A1** | Хаб лобби: табы; **Состав** (упрощённые карточки); **Настройки** имени; **дерево видимости** + пресеты + «глазами игрока»; сразу **mobile layout** + кит; мастер **Смотреть** чужой лист (read-only) | нет | текущие Lobby/Member API |
| **A2** | **Сессии**: создать, отметить присутствующих, список, вход в `/sessions/:id` | нет | seats → attendance |
| **A3** | **Стол**: полные карточки по видимости; live-лента; **лог бросков**; бросок с листа / ввод физ. куба → лента; realtime-шина | **да** | канал сессии |
| **A4** | **Дневник мастера**: посты (текст/глава/ссылка на сеттинг/URL-картинка); пагинация; «закрыть сессию → итог в дневник» | желательно | A2–A3 |
| **A5** | **Чаты** (публичные каналы) + **письмо мастеру** (тикет+тред, бейдж); сайдбар на сессии | **да** | A3 шина |
| **A6** | **Заметки**: личный блокнот + общая доска; быстрая заметка на сессии; мастер видит личные | да для коллаба | A5 или общая шина |

**Порядок A1→A6 подтверждён.**  
Сеттинг-вики в A не входит (только заглушка таба / текущие `world_notes`).

### A — модель данных (эскиз)

- `LobbyVisibilityProfile` — JSON дерева полей + пресет + режим истории событий.
- `PlaySession.attendance` — кто отмечен пришедшим (поверх или вместо чистых seats — уточнить в реализации: seats = состав за столом, attendance = «пришёл»).
- `SessionEvent` — live-лента (типы: roll, note, system, …).
- `DiceLogEntry` — отдельный лог бросков (связь с сессией; не обязан дублироваться в дневник).
- `CampaignJournalEntry` — посты дневника лобби (мастер; опционально `from_session_id`).
- `ChatChannel` / `ChatMessage` — каналы лобби.
- `MasterLetter` — тикет+сообщения; бейдж по `character_id` / имени.
- `Note` — `scope: personal | party | master`; `author_id`.

## 4. Фаза B — Сессия / бой

Цель: цельный боевой стол для офлайн-мастера. Сырое не выкладываем.

| Подфаза | Содержание |
|---------|------------|
| **B1** | Панель мастера на карточках: вдохновение, состояния (без подтверждения); отображение напарников отдельными карточками |
| **B2** | Эффекты на союзников с листа (выбор цели → эффект на обоих листах → корректное снятие); концентрация |
| **B3** | Противники: бестиарий + конструктор своего НПС; посадка в бой; ХП по видимости |
| **B4** | Инициатива (бросок / ручной ввод); ход; базовая боевая сцена |
| **B5** | XP после боя из бестиария (деление на участников) + ручная выдача XP |
| **B6** | Лут: находка → распределение игроками → OK → инвентарь; позже пороги проверок / общий vs индивидуальный обыск |
| **B7** | Шаблоны энкаунтеров |
| **B8** | **Умный генератор боёв** (см. §5) — отдельный R&D |

B1–B2 пересекаются с must-have по напарникам/бафам — не отодвигать за генератор.

## 5. Генератор боёв (B8) — продуктовое ТЗ

Проблема dnd.su: «сложный» бой оказывается лёгким из‑за артефактов, расходников, способностей, заклинаний.

### Вход мастера
- Целевая сложность (шкала продукта, не слепой CR).
- Режим: все сразу / **волны**.
- Тип локации (влияет на тактику/предложения).

### Анализ пати (максимум сигналов)
Листы участников сессии: уровень, класс/подкласс, Хиты/КД, атаки, заклинания, ресурсы, артефакты, расходники, напарники, активные бафы — всё, что реально меняет durabiliy/DPR/контроль.

### Выход
- Предложения: босс волны / помощники / босс битвы.
- Мастер выбирает из предложений по ролям волн.
- Продукт считает **количество** под выбранную сложность.

### Инженерия
Отдельный дизайн-док алгоритма (веса, бюджет сложности, анти-фейлы вроде «игнор магии»).  
Не начинать B8, пока нет ok на модель сложности и список сигналов с листа.

## 7. Частота жестов мастера → приоритет UX

| Жест | Частота (слова Игоря) | UX-следствие |
|------|----------------------|--------------|
| Вдохновение | Каждая сессия, много раз | 1 тап на карточке, realtime |
| Урон/хиты | Игрок сам | Не блокировать игрока мастером |
| Лут | По ходу / обыск | Поток «находка → дележка → инвентарь» |
| XP | Конец каждого боя + вне боя | Авто из бестиария + ручная выдача |
| Состояния | ~1 / 3 сессии | Нужно, но не главный hotkey |

## 9. Критерий ok на старт кода

После ok Игоря:
1. Ветка от **prod tip** (не от упрощённого `main`).
2. Первый код = **A1** (хаб + упрощённый состав + дерево видимости) **в нашем UI kit, mobile-first**.
3. Параллельно — тонкий ADR по realtime-шине (один канал на лобби/сессию), чтобы A3–A5 не переписывать.
4. B8 (генератор) — только после отдельного ok на алгоритм.
5. В каждом PR со UI: скрин/описание mobile (~390px) + desktop; без «на мобилке потом».

**Открытый вопрос (mobile сессии, §0.2):** ок ли каркас чипов `Стол · Лента · Бой · Ещё` на телефоне, или другое разбиение?
