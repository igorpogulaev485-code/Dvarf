## 0. North star

> Сеттинг — не отдельная «вики ради вики». Это **оперативная память кампании**, которая кормит живой стол и дневник.

| Принцип | Решение |
|---------|---------|
| Главная ось | **Сеттинг ↔ Стол ↔ Дневник** (двусторонняя) |
| Не копировать Kanka целиком | Берём механики хранения/скорости ввода; визуал и IA — наш кит |
| Скорость мастера | Создать НПС/локацию/квест **не уходя** со страницы / со стола |
| Секреты | Игрок видит только то, что мастер раскрыл — на странице, связи, блоке, пине |
| Один мир на лобби | Сеттинг принадлежит лобби; все сессии наследуют |
| Mobile-first | Быстрый поиск, quick create, reveal — жест одной рукой за столом |

**Уже есть на проде:**
- **C1–C4:** дерево · связи · reveal · embeds из дневника/чата · `world_notes` → корень  
- **C5–C9:** типы + шаблоны + quick create/bulk · `@mentions` · `gm_body` · связи v2 (пресеты / bi / visibility) · теги + недавние  
- **T1–T5:** handoff со стола → вики · reveal mid-session · лор-панель на сессии · квест-статус ↔ дневник · «открыть за столом» из дневника  
- **D1:** артефакты сеттинга → лист (отдельная ось, тоже на проде)

**Ещё не делаем без запроса:** карта + пины (C10) · relation explorer (C11) · attitude/цвета рёбер · 20 модулей Kanka.

## 1. Что обязательно перенять у Kanka (и как адаптировать)

### 1.1 Связи и зависимости (Relations)

**Как в Kanka:**
- Связь = ребро с **подписью** (`relation`), опционально attitude −100…100, цвет, pin.
- `two_way` — зеркальная обратная связь.
- `visibility` на самой связи (all / admin / self…).
- Mentions в тексте → автоссылки; private target → «unknown» для игрока.
- Отдельный web/explorer отношений (premium).

**Как у нас на проде (после C8):** смысловые связи с пресетами label · bidirectional · `visibility` all|gm · mention-рёбра из `@`/`[[…]]` (C6). Attitude / цвет / отдельный web — не берём.

**Что берём (обязательно):**

| Механика | Dvarf-решение |
|----------|----------------|
| Подпись связи | Уже есть `label` — сделать обязательной для «смысловых» связей (пресеты: правит / живёт в / член / соперник / нанимает / знает секрет…) |
| Двусторонность | `bidirectional` при создании → второе ребро (или флаг + автобэклинк с зеркальным label) |
| Секретность связи | `visibility: all \| gm` (минимум); цепочка: если target не revealed — игрок не видит ребро |
| Зависимости ≠ навигация | Два слоя: **иерархия** (`parent_id` дерево) и **смысловой граф** (links). Не смешивать |
| Автосвязи из текста | `@Название` / `[[Название]]` при сохранении создают/обновляют mention-рёбра (отдельно от ручных «смысловых») |
| Превью глазами игрока | Уже есть для вики (C3) — расширить на связи и блоки |

**Не берём сразу:** attitude −100…100, цвет рёбер, отдельный «View web» как продукт (можно позже как debug/premium UX).

### 1.2 Типы сущностей + шаблоны полей

**Как в Kanka:**
- ~20 модулей с разными полями; custom modules (premium).
- **Attribute templates** — пакет свойств, автоприменение к типу; nested templates; enable/disable.
- Quick creator + bulk + выбор шаблона той же module.

**Как у нас:** страница = `title + body + parent + revealed`. Типов нет. D1 тянет артефакты/способности → лист (другая ось).

**Что берём:**

**Типы (fixed set, не 20):**

| Тип | Зачем за столом | Минимальные поля шаблона |
|-----|-----------------|--------------------------|
| `location` | Где пати / энкаунтер | регион, атмосфера, опасности, GM-notes |
| `npc` | Кто говорит / квестгивер | роль, disposition, hooks, secrets |
| `faction` | Кто тянет нити | цели, ресурсы, отношение к пати |
| `quest` | Что сейчас в игре | статус, награда, связанные НПС/локации |
| `item_lore` | Артефакт/реликвия мира | (мост к D1 / инвентарю позже) |
| `note` | Прочее / свободная | body only |

Тип — поле страницы (`page_kind`), не отдельная таблица на старте. Дерево остаётся универсальным; фильтр/иконка по типу.

**Шаблоны (`setting_page_templates`):**
- Привязка к `page_kind` (+ опционально к сеттингу или глобальный пресет кампании).
- Набор **полей** (key, label, type: text/long/select/number/url, `gm_only`).
- При создании страницы из шаблона — поля копируются в `page.fields` (JSON) + опциональный стартовый `body`.
- Мастер может править шаблон сеттинга: «мой НПС всегда с блоками Hooks / Secrets».
- Seed: 1 шаблон на каждый тип из коробки.

**Не берём:** формулы атрибутов как у character sheet Kanka; inventory на каждой lore-странице (конфликт с листом); marketplace плагинов.

### 1.3 Быстрое создание (Quick Creator)

**Как в Kanka:**
- Глобальная кнопка / клавиша `N` — создать сущность **не уходя** со страницы.
- Bulk: много имён построчно + шаблон module.
- Из формы связи можно создать target на лету.
- Из `@New_Name` — создать отсутствующую сущность при сохранении.

**Что берём (must-have для хранения сеттинга):**

| Жест | Поведение |
|------|-----------|
| **Quick create** | Bottom sheet / Dialog: тип → шаблон → имя (+ parent опционально) → Enter → страница создана, остаёшься где был |
| **Bulk** | Список имён → N страниц одного типа/шаблона (деревня: 8 НПС за минуту) |
| **Create-from-mention** | `@Новый Культ` если не найден → предложить создать (тип по умолчанию / спросить) |
| **Create-from-link UI** | В «Связать» — «+ создать и связать» |
| **Со стола** | Из панели мастера / ленты: «Зафиксировать в сеттинге» (локация сессии, НПС, квест) — см. §3 |

Hotkey `N` — desktop; mobile — FAB / пункт в «Ещё».

## 3. Усиление Сеттинг ↔ Стол (главный дифференциатор)

Kanka почти не «играет» с вами за столом. Dvarf должен.

### T — Table bridges (параллельно или сразу после C5–C7)

| Слайс | Содержание | Эффект |
|-------|------------|--------|
| **T1** | **Hot handoff со стола → вики:** мастер жмёт «В сеттинг» на карточке противника / имени из ленты / локации сессии → quick create с предзаполненным типом + ссылка обратно на сессию | Лор не теряется после боя |
| **T2** | **Reveal mid-session:** из стола раскрыть страницу/ветку/блок; игрокам toast + пункт в ленте «Открыто: Серые Болота» | Драматургия без ухода в вики |
| **T3** | **Стол читает сеттинг:** в панели боя / энкаунтера — привязка локации и «задействованных» НПС/квестов; клик → превью страницы (sheet overlay) | Контекст не в другой вкладке |
| **T4** | **Квест на столе:** статус квеста (active/done) виден мастеру на сессии; закрытие квеста → опционально пост в дневник (как закрытие сессии) | Вики и кампания в одном жесте |
| **T5** | **Обратный мост дневник → стол:** пост с `page_id` уже есть (C4); добавить «открыть за столом» если сессия активна | Замыкание петли |

Ось T1–T5 **закрыта на проде** — дифференциатор vs Kanka уже в продукте.

## 5. Модель данных (эскиз)

### 5.1 Расширение `setting_pages`

```text
setting_pages
  …существующие поля…
  page_kind      enum: location|npc|faction|quest|item_lore|note
  template_id    FK? setting_page_templates (nullable)
  fields         JSONB  — значения полей шаблона { key: value }
  tags           TEXT[] или M2M setting_tags
  status         для quest: planned|active|done|failed (nullable)
```

### 5.2 Шаблоны

```text
setting_page_templates
  id, setting_id? (null = системный), page_kind, name, body_seed
  schema JSONB  — [{ key, label, type, gm_only, options? }]
  enabled bool
```

Системные шаблоны сидятся миграцией; мастер может форкнуть в сеттинг.

### 5.3 Связи v2

```text
setting_page_links
  …from, to, label…
  kind            semantic | mention     — ручная vs из текста
  bidirectional   bool                  — или отдельное зеркальное ребро
  visibility      all | gm
  created_by_mention_span?  optional meta
```

Unique `(from, to, kind)` или `(from, to, label)` — уточнить в реализации (mention vs semantic могут сосуществовать).

### 5.4 Блоки (C7)

Вариант A (проще): `fields` с `gm_only` + отдельное `gm_body`.  
Вариант B: `setting_page_blocks(page_id, title, body, visibility, sort)`.

Рекомендация: **A для C7**, B если понадобятся несколько именованных секций.

### 5.5 Мосты стола

```text
play_sessions
  setting_location_page_id?   — «где сейчас»
  
encounter / session meta
  linked_page_ids[]           — НПС/квесты в игре

session_events
  type: setting_reveal | setting_page_created | quest_status
  payload: { page_id, … }
```

## 6. UX-контуры (наш кит, не клон Kanka)

### Вики (desktop + mobile)
- Слева/сверху: дерево + фильтр типа + поиск.
- Quick create: FAB / `N` → Dialog из UI kit.
- Страница: заголовок, тип-чип, поля шаблона, body с `@`, блок «Только мастер», связи.
- Переключатель «Как мастер / Как игрок» (уже в C3 preview).

### Со стола (mobile-first)
- В «Ещё» / панели мастера: **Сеттинг** → поиск недавних + «+» quick create + «Раскрыть».
- Overlay превью страницы (не полный уход с `/sessions/:id`).
- После reveal — короткое событие в ленте.

### Критерий приёмки UX
На ~390px: создать НПС из шаблона, связать с локацией, раскрыть игрокам — без горизонтального скролла страницы.
